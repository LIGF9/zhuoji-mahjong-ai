## 摘要

本项目在不依赖任何现成对局数据的前提下，为贵州捉鸡麻将的独山变体（108 张、
不可吃、鸡牌计分、听牌资格制）从零构建了完整 AI 系统：自研规则引擎 → 启发式
教师 → 行为克隆 → 自博弈强化学习 → 复式评测 → 网页人机对局。

当前格局：**0.77M 参数的 `dushan_master`（v1 编码器，自博弈链 s1→s11 产物）
= 5.680**，是全场最强模型。此后我们用更大容量（4.07M / 9.84M）、更强表征
（v3 编码器 63 通道）和改进配方训练学生模型，最好成绩 **4.07M 的
`c4_it2280` = 5.434±0.244**（与 master 差 0.246，边缘不显著），但**未能超越教师**。

通过 30 余段受控实验（每段单变量、2400 副共用牌池配对判读），我们排除了
五条路线并沉淀出一个核心结论（R14）：

> **KL 蒸馏锚（β）既防止策略坍缩、又把学生钉在教师分布之后。β 剂量-反应
> 单调三点互证（0.2→5.434 横盘 / 0.05→5.111 下垂 / 0→3.939 崩塌），熵控制器
> 只保熵不保分。在当前"自博弈 + reverse-KL 蒸馏"的目标函数下，β 单旋钮无解
> —— 学生天花板 = 教师 − 0.16~0.39，与参数量无关。**

§10 列出三个候选下一步方向（提升教师 / 换目标函数 / 定版收口），请求专家判断。

## 1. 背景与问题定义

### 1.1 规则背景：独山麻将（贵州捉鸡变体）

- **108 张**：万/条/筒各 1–9 各 4 张，无字牌花牌；**不可吃**，可碰/杠/胡。
- **唯一计分单位是「鸡」**：幺鸡（1 条）恒为鸡；胡牌后翻牌墙一张定"跟随鸡"，
  翻 9 条时幺鸡升金鸡。每持 1 张鸡，其余三家各付对应分。
- **听牌资格制**：只有听牌（报叫）的人鸡才作数；未听牌者鸡数为 0 且按对方
  鸡数赔付。点胡别人弃牌通常需要"通行证"（无豆时平胡只能自摸）。
- 独山特有规则（`zhuoji/dushan.py` 在通用捉鸡引擎上改写）：点炮归属、
  一炮多响、抢杠、热炮、全烧、黄庄查叫口径等；另有横鸡轮、包杠/包鸡/包大牌
  等计分细节。所有分歧点在 `RulesConfig`/`DushanConfig` 中参数化。
- 决策点：三个动作头（弃牌 28 / 自杠 28 / 响应 4），各带合法动作掩码。
  一局 60+ 决策点，**终局才有唯一回报**（零和、每人每局净分）。

### 1.2 为什么必须自产数据

Botzone 无捉鸡麻将游戏条目；国标麻将公开数据与本项目规则空间几乎不重叠；
官方比赛数据无法程序化获取。因此采用：**自研引擎 → 启发式教师生成 BC 数据 →
自博弈 RL**。红线：任何训练特征只允许来自公开信息（绝不读对手手牌）。

### 1.3 硬件与工程约束（影响全部决策）

- i7-14700K（28 逻辑核 / 20 物理核 / 31.8 GB 内存），**无独显**，AVX2。
- PyTorch 2.6.0+cpu，fp32 强制（AVX2 下 bf16 慢 47 倍，启动时断言禁止 autocast）。
- 训练速度：4.07M 模型 ≈ 20–31 s/轮（采集 ~7s + 更新 ~19s），9.84M ≈ 54 s/轮。
- **内存是头号约束**：训练峰值 ≈18 GB，进程池周期重建不可放宽；判读与训练
  永不并发（R10）。

只有通过预登记判据才推进——这是本项目一切结论可信度的基础。

## 3. 状态编码（v1 → v2 → v3）

**相对视角**：永远把当前决策者放座位 0（下家 1/对家 2/上家 3），一次训练覆盖
四个座位。所有版本严格保持**超集性质**（v2 前 15 通道/前 70 标量与 v1 逐位
相同；v3 前 31 通道/前 98 标量与 v2 逐位相同，均有测试断言）——这是做
"表征单变量消融"的前提。

| 版本 | 规模 | 主要内容 |
|---|---|---|
| v1 | 15 通道 × (3×9) + 70 全局维 | 手牌计数/牌河/副露/现张；全局：牌墙、庄、豆、鸡归属、上一张出牌等 |
| v2 | 31 通道 + 98 全局维 | 追加：牌河最近 3 张时序、现物/筋/生牌危险度、对手潜在需求、向听估计、番型可行性、包鸡风险敞口 |
| v3 | 63 通道 + 130 全局维 | 追加：长时序牌河（12 通道）、**横鸡轮状态**、放铳风险与手牌结构（搭子/孤张显式化）、全局扩展 |

**红线（有测试守卫）**：所有新特征只来自公开信息；`test_no_information_leak`
用「篡改对手手牌不得改变编码」断言守住。特征按 a–g 包组织，可单包开关做
单变量消融。

**教训（spatial head）**：旧结构的 28 个弃牌 logit 共享同一个全局池化向量，
"逐牌定位"只能绕远路；加了 `1×1 conv` 零初始化的逐牌空间头（仅 +130 参数，
严格热启动）修复。

## 5. 训练算法

### 5.1 目标函数（`scripts/selfplay.py`）

A2C 式策略梯度（特意不用 PPO：每轮重采样、1 epoch 更新，clip 收益有限）：

```
L = −E[log π(a|s)·Â] + λ_v·SmoothL1(V,R) − λ_e·H(π) + λ_kl·KL(π‖π_ref) + β·KL(π_teacher‖π)
```

- **优势**：GAE(γ=1.0, λ=0.95)，手内用价值头自举（A6）；按座位标准化，clip(±4)。
- **KL 锚（λ_kl，自适应）**：对**起点策略**的反向 KL 惩罚，防跑偏；控制器按
  每轮 KL 率调节（危险线放大 ×1.6 / 宽松缩小 ÷1.4，clamp [0.01, 0.5]）。
- **KLT 蒸馏（β）**：对**教师策略**的 reverse-KL：`KL(π_t‖π_θ)=Σ π_t(log π_t − log π_θ)`。
  方向是刻意选择（A4）：质量覆盖方向，学生在教师认为可能的动作上贴近即可，
  保留自身多峰探索；forward-KL 会把分布压进教师众数提前锁死。
- **熵控制器**：`ent_coef ← clip(ent_coef·exp(η(H*−H)), 0.01, 0.5)`；H* 由启动期
  熵滑动均值 × target-ratio(0.95) 标定，带死区与贴边报警。
- **对手池/座位混合**：`master_seat_prob`（如 0.40）给教师分座位换对手（**只换
  对手，不改监督信号**）；`--klt-teacher` 把蒸馏教师与座位对手解耦（2026-10-19
  修复的一物两用 bug：β 退火到 0 时旧实现会把座位对手一起弄丢）。
- **探索**：ε-greedy 0.03→0.01 退火；温度 1.2；`past-prob 0.3`（重放历史分支）。
- 优化：Adam，lr 恒 1.2e-5（冷启动续训必须恢复优化器状态或 lr-warmup）。

### 5.2 采集与运行形态

向量化自博弈：`games-per-iter 192`、batch 512、12 个采集 worker、24 推理线程；
进程池每 150–250 轮重建防内存累积；每轮快照池滚动保存（`snapshot-keep 4`）。
长跑全部以平台后台任务 + 链式 finalize 方式执行（沙箱每次工具调用结束会清理
进程树，这是踩过坑后的固定模式）。

## 6. 评测与判读方法论（★ 请专家重点评审）

### 6.1 为什么训练内 eval 不可信

训练内 40 副评测 CI ≈ ±1.9 分，而真实代际提升只有 ~0.3 分。曾因此发生
winner's curse：s7 评测分 8.60 高于 s11 的 7.231，2400 副对位赛证明 s11 实际
更强（+0.319±0.288）。**40 副的"最佳点"能把段内最差点排成最好。**

### 6.2 共用牌池配对评分（`score_checkpoints.py`，唯一可信口径）

1. **共用牌池（common random numbers）**：所有检查点打**完全相同**的牌
   （第 r 副 seed = f(seed0, r)，与检查点无关）；对手三位固定（启发式教师 /
   指定模型混合）。
2. **复式轮换**：每副牌让检查点坐遍 4 个座位取均值，四座位共用同一牌 seed。
3. 于是"同一副牌上两检查点的分差"是**配对观测**：2400 副 CI ≈ ±0.24–0.27，
   1200 副 ≈ ±0.31。
4. 输出各检查点 `level`（分值水平，含对手/座位固定的偏倚，只作参考）与
   **相对锚点的配对净分差 ±CI**（决策只看这个）。

### 6.3 决策铁律 R1–R14（全部由真实事故提炼）

| # | 铁律 | 一句话 |
|---|---|---|
| R1 | 单旋钮同起点 | 同时改 ≥2 个量（含换起点）不可归因 |
| R2 | 0.2 量级结论必须 2400 副 | 1200 副的"显著"常是回归均值 |
| R3 | 增益判据 Δ≥+0.40 且 CI 下界>0 | 低于此为零结果；后段按预登记用更小的门槛，但结论降档登记 |
| R4 | 训练量类旋钮全部排除 | 堆轮次/加 epoch/加数据/长训练四类实验均≈0 或负 |
| R5 | 段内 eval 只当熔断器 | 连续 3 点单调下滑即停段；绝不选点 |
| R6 | 选点只用 2400 副，看段首 vs 段末 | 防 winner's curse |
| R7 | 超参不得顺手缩一点 | 曾因 β 0.4→0.06 无 A/B 连滑，损失 300 万样本 |
| R8 | 负结果必须写作用域 | "BC 冷启动有害"≠"一切向强策略学习有害" |
| R9 | 报警阈值随配方派生 | 固定阈值产生假 FAIL 会埋掉真信号；改动须跑历史段回归 |
| R10 | 判读与训练永不同发 | 内存 70%+ 并发会 OOM |
| R11 | KL/熵/段内 eval 都不是强度代理 | β 放大 83×、klt 降 64%，level 只动 +0.18（CI 内） |
| R12 | 辅助头梯度须核账+预热；净有害即判死 | aux 梯度占比 14% 仍显著劣，损伤∝注入量 |
| R13 | 新段起名前查 history/judge/ckpt 三类产物 | 段名撞车会让 --history-append 静默载入旧配方记录 |
| R14 | KL 锚既防坍缩也限制超越 | 见 §9；β 剂量-反应三点单调互证 |

### 6.4 实验纪律

- 每段**预登记**判据（通过/部分/判负三档 + 具体数字），跑完按预登记口径归档，
  不允许事后挑口径。
- 健康度自动检查（A1 熵/A3 冻结尖峰/A6 优势/A7 KL 锚/A8 样本量区间等）只判
  "训练是否健康"，不判"是否变强"（R11）。
- 全部产物留痕：段配方在 `SEGMENTS`、原始日志、history.jsonl、judge.json、
  归档 MANIFEST、以及每段一份判读报告（`reports/`）。

## 7. 训练实验全史

### 7.1 教师链（0.77M，v1 编码器）

启发式教师 BC → 自博弈 s1…s11（分段晋升验收）。途中**唯一大幅增益杠杆是
s4a 的 β=0.40 蒸馏：+1.127±0.412**（起点低、headroom 大，见 §7.2 诚实边界）。
最终 `dushan_master`（=s11）**5.680**。

### 7.2 β 阶梯与"术语连坐"事故（项目最贵的教训）

- s4a 后，β 在无任何实验的情况下被逐段顺手砍到 0.06（s4b6→auto4→m2p1/p2/p3
  全部 ≈0 或负），7 段 ≈300 万样本停在 level≈5.0。
- 根因复盘：**`teacher_prob`（换对手）、`--klt-beta`（蒸馏权重）、BC 预热
  （监督初始化）三件东西被一个 "teacher" 串在一起连坐**，其中两件的负结果
  被外推到第三件上。→ 由此立 R1–R11。

### 7.3 M2 学生链（4.07M / 9.84M，v3 编码器）

受控实验流水（全部 2400 副判读，Δ 相对各自预登记锚点）：

## 8. 核心发现（证据强度与边界）

### 8.1 学生天花板 = 教师 − 0.16~0.39，与参数量无关

四段独立证据（学生末点 − 教师水平）：c3(d3 教师 5.325)→−0.32；
c4(master 5.680)→−0.246；e1(master)→−0.39；f2(d3, 9.84M)→−0.16。
跨参数量（4M/10M）、跨教师水平一致。**加容量/加轮数/加强陪练三路失效共用
这一条解释。**

### 8.2 R14：KL 锚既防坍缩也限制超越（本项目最重要的机制性结论）

β 剂量-反应（同一 c4 起点、同一 2400 副口径、单旋钮）：

| β | 末点 | 机制读数 |
|---|---|---|
| 0.2 | 5.434（横盘 850 轮） | 拉力足够 ⇒ 站得住，但贴死教师 |
| 0.05 | 5.111（轻度下垂） | 拉力不足 ⇒ 缓慢漂移劣化 |
| 0 + 熵控 | 3.939（崩） | 熵被控住（H 0.6±），**分数照崩** ⇒ 崩因不是熵 |

三点单调互证 + g1r（退火过程中 klt 0.23→0.50 而分数稳、β=0 即崩）⇒
**KL 锚的作用是锚定策略分布本身、防止策略梯度在稀疏终局奖励下的过度优化
漂移；它同时把学生的可达集合限制在教师分布邻域**。"保熵的解绑"
（m2g2）与"小拉力受控超越"（m2g3b）两条替代路径均已受控判负。

**诚实边界**：以上全部结论都在"自博弈 + reverse-KL 蒸馏 + 线性价值头 GAE"
这一目标函数族内成立。我们尚未测试目标函数层面的结构性改动（§10.2）。

### 8.3 其他已固化结论

- **训练量不是瓶颈**（在 5.0 之后）：c3 段证训练量在爬升期有用、c5 段证
  5.41 之后无用（klr 锁死 0.0007，klt 卡平台）。
- **容量红利一次性兑现**：10M 前 600 轮 +0.490 显著、后 600 轮 +0.196 ns；
  性价比负（时间 ×1.8，终点更低）。
- **辅助稠密监督净有害**（R12）：即使 aux 梯度占比仅 14%。
- **熵自然稳态 ≈ 段首的 91.6%**：把 H* 设更低必不可达；temp 调熵已证伪。
- **BC 冷启动有害**（−0.529，`--freeze-old` 冻结旧参数无法补偿新通道扰动）；
  但其作用域仅限"从零初始化新 encoder 的 BC 冷启动"（R8）。

## 10. 供专家评审的开放问题（请求判断）

**问题：在 CPU-only、~20 s/轮、日均 <20 h 训练预算下，如何得到显著超越
5.68 的模型？**

### 10.1 方向 A：提升教师本身（我们当前的首选）

逻辑：c4 链证明教师质量是学生上限的主因（+0.27），且 master 仅 0.77M、
训练管线老（v1 编码器）。候选：① 用 v3 编码器 + M1 架构**重训教师**（但
4M/10M 学生从未到过 5.68，重训能否超越存疑）；② 给 master 继续 12h 级自博弈
长训（其自身天花板未知）；③ master + KLT 蒸馏自举（master 蒸馏自己？）。
**疑虑：教师继续自博弈可能同样被"训练量到顶"卡住——c5 的教训。**

### 10.2 方向 B：换目标函数（撤 KL 依赖）

R14 表明问题在目标函数层面。候选：① 信任域课程 / 渐进锚点释放（结构化地
放宽而非线性减弱 KL）；② league / Prioritizedized self-play（按胜负采样
对手，避免同策略互相强化）；③ off-policy 修正或更大 batch 降梯度噪声
（稀疏奖励下漂移的根源是否是梯度噪声？**这是我们的机制疑点，请专家判断**）；
④ model-based / 搜索增强（MCTS 之类在 3×9 网格 + 掩码下的可行性）。

### 10.3 方向 C：定版收口

c4_it2280 进 UI 对战链路，训练转低频维护，把算力留给规则侧打磨。

### 10.4 我们特别希望专家评审的点

1. §6 判读口径（共用牌池配对 + 预登记 + R 系铁律）是否有漏洞或更优实践？
2. §8.2 R14 的解释（"锚定分布防漂移"）是否有更准确的机制表述？β=0 崩塌
   是否可能是其他原因（如价值头过拟合、优势估计偏移）？
3. 教师差距 0.246 在 2400 副下边缘不显著——是否值得再花 2400×2 副确认
   "学生已平教师"？若是，方向 A 的必要性是否下降？
4. 麻将（不完全信息、稀疏零和回报）在 CPU 预算下，有没有我们没想到的
   已被验证有效的路线（文献或实践经验）？
