## 2. 口径

- **设备**：Android 模拟器 `zhuoji_test`（arm64-v8a, API 36, 4 vCPU, 1536 MB），
  宿主 Apple Silicon。图形式启动被禁用（`-no-window` + `swiftshader_indirect`），
  验收全部走 `adb`，截图由 `adb exec-out screencap` 取得。
- **为什么拿模拟器当判据**：它的 CPU 走 HVF 直通、指令集与本机一致，
  小算子开销只比宿主慢 1.3–3.5×（见 §3.1 贪心一行）；但**大批量矩阵乘会放大到 ~12×**，
  所以下面的搜索档耗时是「偏悲观」的上界，不能当低端真机的预测值。
- 所有耗时均取自 App 自检日志 `[offline] bench …`（`offline/src/bench.rs`，
  启动后后台线程跑一次并写入 logcat）。

## 3. 推理耗时（同一份代码、同一决策点、同一 seed）

### 3.1 设备端（arm64 模拟器，4 线程）

| 档位 | champ_slim_s | dushan_master |
|---|---|---|
| 贪心（单步前向） | **1.08 / 1.87 / 3.79 ms** | **0.64 / 0.65 ms** |
| 深算 N32 | 1249 / 1253 / 1370 ms | 1078 / 1133 / 1170 ms |
| 极算 N128 | 6840 / 6919 / 7175 ms | 6962 / 6995 / 7195 ms |

（三次冷启动的重复测量，单位 ms；贪心量级差异是首帧抖动，稳态 ~1 ms。）

### 3.2 宿主机（M 系列，4 线程分块前向）

| 档位 | 单线程 | 4 线程 | 加速比 |
|---|---|---|---|
| 贪心 | 0.51 ms | 0.51 ms | —（n<8 不起线程） |
| N32（master） | 440 ms | **151 ms** | 2.9× |
| N128（master） | 1738 ms | **552 ms** | 3.15× |
| N128（slim_s） | 1683 ms | 535 ms | 3.15× |

**确定性**：`DUSHAN_MT=1` 与 `DUSHAN_MT=4` 的 N32 Q 向量逐位相同
（指纹 `0.570439,0.607039,-0.066160,…`，11 个动作全等）——分块是纯数据并行，
行内计算顺序不变，**线程数不改变棋力**。

### 3.3 由此得到的档位决策

1. 贪心在设备上是 **1–4 ms**，可以每回合都算（推荐浮牌/大师建议无感）。
2. N32 是 **1.1–1.4 s**、N128 是 **6.8–7.2 s**，而 `/api/hint` 在每个我的决策点都会被调；
   选搜索档等于每步停顿 1 秒以上，N128 直接不可用。
3. P0 三臂实测（`reports/P0-学生N32搜索红利.md`）已经给出「学生换搜索」没有可测收益
   （配对差 −0.978±0.846，CI 跨零），所以**没有强度理由为搜索付延迟**。

⇒ 离线版默认档 = `model:champ_slim_s`（贪心），搜索档保留在设置里供手动选择。
实现方式：`dushan.html` 的 `DEFAULT_STRATEGY` 改为读取
`window.__DUSHAN_DEFAULT_STRATEGY`，离线服务出站时注入该全局量；
联网版不注入，默认仍是「极算 N128」，**两边行为不分叉**。

## 5. 四项 Android 行为（逐条实机验证）

### 5.1 沉浸全屏（隐藏状态栏/导航栏）

`dumpsys window` 中 `InsetsSource type=statusBars … visible=false`，
`navigationBars` 同；截图无状态栏、无导航栏，内容铺满 2280×1080。
`onWindowFocusChanged` 每次获焦重放，兼容会自己恢复系统栏的厂商 ROM。

### 5.2 5 分钟无操作后允许息屏

把系统息屏超时临时调到 10 s（`settings put system screen_off_timeout 10000`），
然后**完全不触摸**，读 `dumpsys power`：

```
ACQ 14:35:31.818  WindowManager/displayId:0 (screen-bright,on-after-release)  ws=…offline
REL 14:40:31.731  WindowManager/displayId:0
```

ACQ→REL **正好 5 分 00 秒**（`IDLE_TIMEOUT_MS = 5*60*1000`），释放后 10 s 内
`mWakefulness=Asleep`——即「5 分钟内有触摸就续期，超过就交回系统息屏」按设计生效。

### 5.3 幺鸡 logo

桌面图标（launcher）、系统启动图、应用启动页、首页左上角四处一致；
APK 内 `mipmap-{m,h,xh,xxh,xxxh}dpi` 全套 + `mipmap-anydpi-v26` 自适应图标。

### 5.4 横屏 + 可开小窗

- 单窗口：`screenOrientation="sensorLandscape"`，实机为横屏。
- 小窗：`am start … --windowingMode 5` 后 `dumpsys activity` 显示
  `mWindowingMode=freeform`、`mBounds=Rect(74,906-1006,1374)`（932×605 悬浮窗），
  页面在窗内正常渲染（截图 `runs/emu_freeform.png`）。
  机制：`resizeableActivity=true` + 进多窗口时把方向请求临时放开为
  `UNSPECIFIED`（固定方向的 Activity 在小窗里会被 letterbox，这是原 v1.1.0 的根因）。
- 注：小窗内是页面自身的响应式排布，未做小尺寸专门适配。

### 5.5 断网可玩

`airplane_mode_on=1` + `svc wifi disable` + `svc data disable`，
`ping 8.8.8.8` 返回 `Network is unreachable`；随后冷启动 → 开局 → 连续 6 手出牌
→ 三家 AI 出牌 → 大师建议每回合正常刷新（`打一万 35.0%` → `打五筒 34.6%` → `打三万 40.3%`），
余牌 55→52→45 递减，`logcat` 无 panic / FATAL / ANR。

## 6. 实机暴露的 5 个问题与修复

| # | 症状 | 根因 | 修复 |
|---|---|---|---|
| 1 | 玩家头像全是碎图标 | 头像文件名是中文（`/assets/avatar/boy/云天明.jpg`），请求行里是 `%E4%BA%91…`，直接拿百分号串查 `include_dir` → 404 | `http.rs::static_resp` 先 `unquote` 再查表（联网版由 Python 侧解码，Rust 侧漏了） |
| 2 | 每次启动设置全丢 | 服务用 `serve(0)` 随机端口，而 localStorage 按 **origin（含端口）** 隔离 | 固定 `127.0.0.1:8791`，被占才退回临时端口 |
| 3 | 默认档是「极算 N128」，手机上 7 s/步 | 页面 `DEFAULT_STRATEGY` 写死 128；写 localStorage 无效，因为页面自己的 `migrateCfgVersion()` 会用常量覆盖 | 页面加 `window.__DUSHAN_DEFAULT_STRATEGY` 钩子（一行，联网版不注入即无影响），离线默认改贪心 |
| 4 | 冷启动前约 1 s 纯黑（后又变纯白） | 主题没有 `windowBackground`，系统启动图用的是默认底色 | `themes.xml`/`values-night` 加 `android:windowBackground` + `windowSplashScreenBackground = #07261d`（与启动页毡面同色） |
| 5 | **启动页报「Command engine_status not allowed by ACL」，点重试无效** | `tauri.conf.json` 未显式声明 `security.capabilities`；CLI 生成的运行期配置 `capabilities: []` → 全部 IPC 被 ACL 拦死 | 显式写 `"capabilities": ["default"]`，构建后核对内嵌配置含 `["default"]` |

> 第 5 条最危险：它会让 App **完全打不开**，而且是否出现取决于上一次生成的内嵌配置，
> 属于「偶发但致命」。已按「构建后断言」的方式收口（见 §7）。

## 7. 复现命令

```bash
# 构建（增量 30 s 内）
bash runs/build_offline_apk.sh

# 装 + 起 + 看自检
adb install -r tauri-offline/src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
adb logcat -c; adb shell am start -n com.zhuoji.mahjong.offline/com.zhuoji.mahjong.MainActivity

# 宿主机基准（含确定性与多线程加速比）
cd offline && DUSHAN_MT=4 ./target/release/search_bench
```

## 8. 遗留与建议

1. **真机复测一次 `bench`**：模拟器的大批量前向比宿主慢 ~12×，比真机可能更悲观；
   装到目标机型后只需看一行 `[offline] bench greedy … n32=… n128=…` 即可定档。
2. **搜索档要不要优化**：若希望手机上也能用「深算」，可选项依次是
   降 `n_det`（N8/N16）、int8 量化、把搜索挪到对手思考的空档（异步预取）。
   当前不做：P0 没有证据表明搜索能提升棋力。
3. **小窗内的布局**未做专门适配（沿用页面响应式），只在极端窄窗会显拥挤。
4. 对局历史云同步、冠军模型热注册、局域网多人**不提供**（离线定位如此），
   `/api/history*`、`/api/replay`、`/api/stats` 返回空结构而非报错，前端不崩。
