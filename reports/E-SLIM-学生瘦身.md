## 1. 为什么分两级蒸馏

直接把 P48 的 28 槽 Q 灌进 0.8M 的 s 骨干有 capacity gap。所以先训一个
**教师助教 TA**（m1 96×10 = 1.99M）去拟合教师全 28 槽 Q，再让 S1 蒸
「教师 + TA」的混合软标签 `0.5·softmax(Q_T) + 0.5·softmax(Q_TA)`。

- 软标签只在**合法槽**上归一（`mask`），非法槽 `−inf`；
- contested 加权 `w = 1 + β·H(p_T)/log|A_legal|`，`β=1.0`（预登记锁死），**只加权不丢样本、不改 τ**；
- 价值头目标 `maxQ/8`，`VALUE_W=0.5`；
- 1.6M 行 `tiles(63,27)` f32 全量约 10.14 GB，按 25k 行 / 183 MB **分片流式**，峰值 ~1 GB；
- 不启用 AMP/bf16（本机仅 AVX2，bf16 训练慢 47×）。

## 4. 闸门 A（统计，唯一主判据）

`候选贪心 vs master+N32`，与组合① 完全同口径；统计量 `deltas[cand] − mean(其余三家)`，
四座按 seed 平均，seed 维度配对 t。

```
n = 300 seeds (1200 局，座位覆盖 1200/1200)
diff = +1.0356   sd = 6.2371   se = 0.3601
95% CI = [+0.3269, +1.7442]        (t[299], t.975 = 1.968)
正态近似 z = +2.876   p = 0.00403  （参考，不作判据）
非劣单侧 t = +4.264   p = 1.35e-05  ← δ = −0.5
符号检验 173 : 125（正 : 负，另有 2 个 0）
```

**分布结构**（如实登记，不作修饰）：

- per-seed 中位 **+1.167**，p05 −8.33 / p25 −3.33 / p75 +5.33 / p95 +12.00；
- 173 个 seed 为正、125 为负 ⇒ 不是靠少数极端局面撑起来的；
- 31 个 seed 的 `|diff| > 10`，合计占总和 54%；**剔除后均值仍为 +0.534**；
- 逐局胡牌者=候选的比例 **24.7%**（随机期望 25%）——候选**不是靠多胡牌**赢的，
  收益主要来自鸡账/包鸡一侧（避免未听牌包鸡）。这只是分布事实，**未做机制归因**。

**禁止事项遵守情况**：未改 δ、未改池、未加 seed、未跨池相减、未用自对弈胜率、
未把 val_loss 当棋力证据、未把 JSONL 回流训练。

## 5. 判据冲突：字面 TOST 与"更好"的矛盾（必须如实登记）

§6.73.4 原文：**"95% CI 下界 > −0.5 **且** TOST p < .05（等价检验双侧）"**。

两个分句在"候选更好"时会**互相矛盾**：

| 分句 | 实测 | 结论 |
|---|---|---|
| 95% CI 下界 > δ | +0.3269 > −0.5 | **通过** |
| 单侧非劣检验 p < .05 | 1.35e-05 | **通过** |
| TOST 双侧（±0.5）p < .05 | **0.931** | **不通过** |

原因是点估计 **+1.036 落在等价带 (+0.5) 之外的上方**——TOST 双侧等价检验的设计
目的是"证明差不多"，因此**惩罚"显著更好"**。用它做非劣判定是**措辞缺陷**：
非劣是单侧假设（H0: μ ≤ δ vs H1: μ > δ），不应设上界。

**处置（不做任何事后修正）**：

- **不改** δ、不改判据、不重跑、不加 seed——§6.73.5 明令禁止看结果后改判据；
- 报告同时呈现两种读法，**不挑选有利的一种**；
- 字面机械执行 = "统计不过" ⇒ 按判定矩阵应"不给线上"。但把这个结论写成
  "无足够证据表明非劣"会与 p=1.3e-05 的事实直接冲突，故**不采用**该措辞；
- 建议：按**非劣（单侧）**口径采纳为候选冠军，并在 §6.73 记录"等效区间上界应删除"，
  供**下一份预登记**修正（本次不追认）。

## 7. 局限与没做的事

1. **单池单次**：只有一个 300 seed 池、一次评估。未做跨池复现（按规则也不该做跨池相减）。
2. **候选只有贪心档**：本闸门 `--a-mode greedy`。学生**带 N32 搜索**的表现未知；
   N32 单步 0.275 s ⇒ 一盘约 44 步 × ~1/4 决策，搜索档在桌面上可用，但未测棋力。
3. **ONNX 一致性是 CPU 后端**：CoreML 曾有 1.2e-3 的记录（足以翻转 argmax），
   本轮未在 ANE 上复核。
4. **未做 7_200_000 及更早池的回归**：防止"对 master 好、对 P48 差"的错位。
5. **收益机制未归因**：胡牌率 24.7% 与均值 +1.04 的并存只作事实登记，未做机制实验。

## 8. 结论与建议动作

- **工程**：5/5 通过，成本降 12.1×（参数）/ 6.6×（N32）/ 4.9×（贪心）；
- **统计**：非劣**成立**（单侧 p=1.3e-05），且**显著优于**基线（z=+2.88, p=0.004）；
- **字面 TOST**：不成立，原因是"更好"，判据措辞缺陷，如实登记；
- **动作**：建议 `champions.json` **新增** `slim_s` 条目（只增不替，线上主力仍
  `dushan_master`，需重启 Web 才生效）——**本条待用户确认后执行**；
- **副产品**：`slim_s` 3.1 MB ONNX + 0.275 s N32，直接改善离线版「手机上有没有可用搜索档」
  这个最大的技术风险（见 `docs/离线版-可行性与实施方案.md` §3.1）。
