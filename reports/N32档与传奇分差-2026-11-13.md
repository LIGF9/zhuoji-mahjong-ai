# N32 深算档 vs 传奇（贪心）· 分差评测

2026-11-13 · 口径：`reports/离线版-四档强度矩阵.md` 同一套配对协议

## 一句话结论

**在 400 seed × 四座 = 1600 副的样本下，N32 相对传奇贪心没有可测的强度优势**；
点估计甚至略负（**−0.072 分/副**），95% CI 跨 0。按预登记口径只报
「本样本量下无足够证据」，**不写「持平 / 无差异 / 搜索无用」**（p>.05 不等于效应为零）。
但置信区间上界是 **+0.43 分/副**，所以可以明确排除「N32 带来大幅强度提升」：
它并非一个实际更难的 AI，只是**更慢、更耗算力**的推理方式。

## 评测对象（就是打包进 App 的那份代码）

| | 候选 | 对手三家 |
|---|---|---|
| 策略串 | `search32:champ_slim_s` | `model:champ_slim_s`（贪心） |
| 实现 | `offline_core::search::deep_q`：PIMC 32 路确定性推演，`ff_cap=24, topk=3, ply=1` | `offline_core::policy::Net::choose` 单次前向 |
| 权重 | `models/onnx/champ_slim_s.onnx`（同一份，0.82M） | 同左 |

**N32 不是新模型**：同一份权重 + 推理时 32 路推演。这里测的是桌面 .app /
在线宿主（Rust 内核）新加的第 5 档，参数与 Python 网页在线版
（`ply=3, n_det=32`）不同，所以不能直接引用
`reports/P0-学生N32搜索红利.md` 的臂 C。

工具：`offline/src/bin/n32_arena.rs`（本轮新增），协议与
`offline/src/bin/tier_arena.rs` 一致：

- 每个 seed **同一副牌墙**，候选轮流坐 0/1/2/3 号位，其余三家全坐对手档；
- 统计量 `cand_delta − 其余三家均值`，seed 内四座平均后再跨 seed 求均值与 95% CI；
- 结算走 `dushan_engine::settle::settle_win / settle_huangzhuang`；
- seed 池 `7_300_000..7_300_399`（与 E-SLIM 闸门 A / 四档矩阵同池），400 seed × 4 座 = **1600 副**；
- 「分/副」= 配对差 × 3/4（四家 deltas 之和为 0，故 `cand − 其余三家均值 = 4/3 × cand`）。

## 原始结果

```
配对差 n=400  mean=-0.097  SE=0.342  95%CI=[-0.767,+0.573]  2×SE=0.684
折合每副（×3/4）: -0.072 分/副   候选领先 seed: 190 / 落后 205 / 持平 5
每副 95% CI ≈ [-0.575, +0.430]，半宽 0.503 分
```

原始数据：`runs/tiers/n32_vs_legend.json`（含逐 seed 值；`runs/` 被 .gitignore 忽略，
本地可复算）。复现命令：

```bash
cd offline && cargo build --release --bin n32_arena
./target/release/n32_arena --seeds 400 --threads 8 --out runs/tiers/n32_vs_legend.json
# 反向配对（传奇 vs 3× N32）：加 --reverse
```

## 成本剖析（按用户「长时任务优先 Rust 快路径」规则）

| 路径 | 单位成本 | 1600 副总耗时 |
|---|---|---|
| Python 在线版同类评测（`reports/P0-学生N32搜索红利.md` 臂 C） | ≈10.35 s/局，跨进程 ORT + JSON | ≈4.6 小时（单进程） |
| Rust `deep_q`（本轮）：本进程 tract 前向 + 内结算 | ≈8.8 CPU-s/副 | 1768 s ≈ **29.5 分钟**（8 线程） |

Rust 快路径把跨进程 JSON / Python 结算全部去掉，并按 seed 分片并行（每个
worker 独占一份 tract 执行计划），是本机能拿到的最低成本。未再降样本量：
400 seed 才能把每副 CI 半宽压到 0.5 分，足以排除「≥0.43 分/副 的增益」。

## 与既有报告的一致性

| 报告 | 候选 vs 对手 | 结论 |
|---|---|---|
| `reports/P0-学生N32搜索红利.md` 臂 C（Python, 120 seed） | 学生 N32 vs 3× 学生贪心 | mean −0.594±0.625，CI 跨 0 |
| 同报告主判据 Δ=A−B | 开/关 32 路搜索 | −0.978±0.846，CI 跨 0 |
| **本报告**（Rust, 400 seed） | N32 vs 3× 传奇贪心 | −0.097±0.342（配对差），CI 跨 0 |

三份独立结果方向一致：**对这份已蒸馏到接近局部最优的学生权重，
32 路 PIMC 在四人局里换不来可测的棋力**。可能原因：
`fair` determinization 只重排别家手牌与牌墙、`agg=max` 在多人对抗中偏乐观、
`ply=1` 只推演一层；而贪心策略本身已足够好，搜索的方差反而吃掉了微小收益。

## 产品含义（重要）

用户先要求「桌面端 / 移动在线端加一个更高难度的 N32 选项」，看到本报告
结论后定稿：**「没有可测的强度区别就不动 AI 模型选项了」**。因此本轮
**整体撤回**试加的 N32 档位（assets.rs 的 cfg 分叉、前端主表新项、
`/api/new` 载荷分叉都恢复上一版），各端 AI 模型选项与上一版逐字一致；
网页在线版冠军组里原有的 `search32:*` 属历史选项，不增不删。

- 若以后真要「更强」：应改用更强权重（`champ_exit_p48`）或更大搜索量
  （N128），需另做配对评测；本轮未改默认、未动权重、未动 champions.json。
- 若只是「给玩家一个可选择的推理模式」：N32 代价是每步约 0.3–1.4 s
  （手机端 1.1–1.4 s/步），在没有强度收益的前提下不值得加。

合规声明：权重、`champions.json`、seed 池、结算口径、四档默认值全程未改动；
本报告只新增评测工具与结论，未据此修改任何产品行为。
