## 0. 一页结论

**三个数字**

| 诊断 | 结果 | 一句话 |
|---|---|---|
| 动作一致率 | **55.1% ± 2.2%**（n=2000） | 低。分歧几乎全在"出哪张牌"（discard 47.5%），而碰/杠/胡/过高度一致（respond 98.2%） |
| 强度差距 | 对 random 只差 **+0.82**；对三教师差 **+2.60**；对 defensive 差 **+3.09** | 不是全面落后 —— **基础牌效已追平，落后的是"和会打牌的人打"** |
| 耗时 | 65.6 s = 采集 12.6 + **update 三段 48.0** + 池重构 3.9 + 评测 3.3 | "22 s 神秘开销"其实是**被误记的 update 内部成本**（OLS R²=0.98） |

**三条行动决定（直接改写 M2-A 配方）**

1. **差距在"低信息局面下的取舍"，不在"信息不足"** → **A9 辅助头（对手手牌预测）降级为"不上"**。
   理由：critic 对局面好坏的排序相关已达 **Spearman 0.76**（M1 的 value 与 master 的 value 排序高度一致），
   而分歧最大的分层是"对手无副露 37.9% / 巡目中早 47.5%"——**约束越弱、信息越少，分歧越大**，
   这更像"风格取舍没对齐"而不是"看不见对手手牌"。
2. **A4 KLT 教师蒸馏是最高优先级杠杆**，β 上限按 §4 的 0.4 执行（诊断给出的理由是：分歧是**排序层面的近似平局**，
   不是固执走另一条路线 —— 分歧时 master 的选择在 M1 分布里平均概率 0.152、**80.8% 落进 M1 的前五**，
   而 M1 在这些局面的 top1 置信度只有 0.371。**它自己也不确定，正好由教师把排序掰过来**）。
3. **A7 吞吐修复加两条（本诊断新发现，合计可省 ~25 s/轮 ≈ +60% 轮次）**：
   ① **采集时顺手回传 `value`** → 省掉优势估计的整批前向（10.2 s/轮，**完全等价、零风险**）；
   ② **KL 锚前向改用 master 规模 / 不每步算** → 省 8.4 s/轮。
   原计划的 pool 判据修复仍有效但只值 3.8 s/轮。

## 1. T0.1 动作一致率分解（`scripts/agreement_probe.py`）

### 方法

在 **2000 个冻结决策点**上严格配对：用 `dushan_master` 与 `dushan_m1_s3` 各跑 25 局自博弈，
在**每一步决策前 `deepcopy` 冻结局面**，然后把同一局面喂给两个模型（temperature=0，确定性 argmax）。
两个模型的输入分布因此逐位相同 —— 避免了"各自对局导致局面分岔"这个最容易造成假结论的坑。

自检：`head` 不一致 0 条、`mask` 不一致 0 条 —— v1 与 v3 编码器共用同一套
`action_head_and_mask`（`encode_v3` 内部调 `encode_v2` → `encode_v1` 取 head/mask，只替换 tiles/glob），
所以动作下标语义逐位可比。这是本诊断能被信任的前提。

### 总体

| 指标 | 值 |
|---|---|
| 整体 argmax 一致率 | **55.1% ± 2.2%** |
| 平均 JS 散度 | 0.172（动作空间 28 维，两个完全不同的分布上限 ln2=0.693） |
| 分歧条数 | 897（44.9%） |

### 按动作头

| 头 | n | 一致率 | 平均 JS | 读法 |
|---|---|---|---|---|
| discard | 1696 | **47.5%** | 0.200 | **分歧几乎全在这里** |
| self_kong | 32 | 93.8% | 0.034 | 暗杠/补杠几乎无分歧 |
| respond | 272 | **98.2%** | 0.012 | 碰/点杠/胡/过 **完全一致** |

> 离散的"要不要动作"（respond / self_kong）两个模型几乎同解；**差异纯粹在"出哪张牌"**。

### 分层

| 分层 | n | 一致率 | master 选择落 M1 前三 |
|---|---|---|---|
| 对手无副露 | 314 | **37.9%** | 69.4% |
| 对手副露 ≥ 2 | 1392 | 60.9% | 85.6% |
| 巡目早 / 中（wall 30–60） | 1239 | 47.5% | 77.2% |
| 巡目晚（wall < 30） | 761 | 67.5% | 89.6% |
| 自己未听牌 | 1512 | 52.3% | 80.7% |
| 自己已听牌 | 488 | 63.9% | 85.7% |
| 对手无人听牌 | 1115 | 50.1% | 78.8% |
| 对手 ≥1 家听牌 | 885 | 61.5% | 85.8% |
| 对手 ≥2 家听牌 | 380 | 65.3% | 87.1% |
| 本步可胡 | 30 | 83.3% | 100.0% |
| 打出幺鸡 | 33 | 48.5% | 75.8% |
| 手中有幺鸡 | 917 | 54.3% | 79.8% |
| 横鸡轮 | 100 | 60.0% | 79.0% |
| **★高价值子集** | 1550 | **58.3%** | 84.0% |
| **★低价值子集** | 450 | 44.2% | 74.7% |

（"高价值子集" = 可胡 ∨ 有对手听牌 ∨ 巡目晚 ∨ 涉及幺鸡；"低价值" = 其余）

**单调规律：约束越强，一致率越高。** 对手牌河/副露的信息越多、巡目越晚、自己越接近听牌，
两者越容易达成一致；反之（局面早期、对手干干净净）分歧最大。

### 分歧结构

| 指标 | 值 | 含义 |
|---|---|---|
| 分歧时 master 的选择在 M1 分布里的平均概率 | **0.152** | M1 没有"强烈反对"，属**软分歧** |
| 落进 M1 前二 / 前三 / 前五 | 37.1% / **59.6%** / 80.8% | 六成是"次序不同"，八成"想到了但没排第一" |
| 不一致时 M1 的 top1 置信度 | **0.371**（一致组 0.718） | **M1 在这些局面自己也不确定** |
| 不一致时 master 的 top1 置信度 | 0.645（一致组 0.888） | 教师有明确偏好 |
| 分歧的两张牌 \|Δtile\| 中位 | **7**（相邻 ≤2 只占 15.8%） | 不是"3 筒 vs 4 筒"的微差，是**结构上不同的取舍**（打万 vs 打条 / 拆对 vs 留对） |
| 分歧组的合法动作数 | 9.2（整体 7.5） | 选择越多分歧越大 |
| critic 排序相关 Spearman(v_M1, v_master) | **0.760** | **价值认知高度一致** → 不是 critic 坏了 |

### 判据落地

计划 §4 的两条判据：一致率整体高（>80%）→ 指向价值头/信念；整体低（~50%）→ 系统性风格差异。

实测 **55.1%，且高价值子集（58.3%）反而比低价值（44.2%）更高** —— 与"关键处出错"的假设相反。
**结论：是系统性风格差异，且集中在低信息局面的出牌取捨上。**

补充一条计划里没预设、但诊断给出的更精确画像：

> M1 的失败模式不是"固执地走另一条路"，而是**在信息不足时策略退化成近似均匀分布（置信度 0.371、
> 熵 1.13+），此时 master 的选择通常就排在它的第 2–5 位**。这正是"策略覆盖/排序未对齐"的特征，
> 而不是"表征缺失"（critic 排序相关 0.76 已经说明表征里该有的信息基本都有）。

## 2. T0.2 强度分解（`scripts/score_checkpoints.py`，共用牌池配对，1200 副 / 场）

四场都是同一副牌池（`seed0=31337`）、同一批对手种子，两个模型在**同一副牌上配对**，
所以 `vs_anchor`（master − M1）是无偏的配对净分差。

| 对手配置（3 席） | master level | M1-s3 level | 配对差（master − M1） | M1 占 master |
|---|---|---|---|---|
| `random × 3` | +15.110 ± 0.343 | +14.289 ± 0.452 | **+0.822 ± 0.516** | **94.6%** |
| `balanced + aggressive + defensive` | +5.531 ± 0.345 | +2.927 ± 0.359 | **+2.604 ± 0.447** | 52.9% |
| `aggressive × 3` | +6.455 ± 0.343 | +3.551 ± 0.452 | **+2.905 ± 0.455** | 55.0% |
| `defensive × 3` | +5.462 ± 0.343 | +2.369 ± 0.452 | **+3.093 ± 0.422** | **43.4%** |
| （参照）heads-up 2v2 各两席 | — | — | **+3.105 ± 0.436** | — |

每场 1200 副 × 4 座轮换 × 2 检查点 = 9600 局，多进程 15 worker，**2.7–2.9 min/场**。

### 结论

1. **不是"全面落后"。** 对随机对手 M1 拿到了 master 的 **94.6%** —— 说明"怎么把牌打胡"这件事已经学会。
2. **差距随对手变强而扩大。** 对随机 +0.82 → 对三教师 +2.60 → 对单一风格 +2.9~3.1 → heads-up +3.11。
   落后的是**博弈/对抗层面**（读牌、取舍、与有意图的对手周旋），不是基础牌效。
3. **对保守型对手最吃力（defensive 场只有 43.4%）。** 与 T0.1 完全自洽：
   defensive 教师副露少、牌河干净 → 正好对应 T0.1 里一致率最低的"对手无副露 37.9%"。
   **即：低对抗、需要精细取舍的局面，是 M1 最薄弱处**（而不是"高强度对抗"局面）。

> **口径警示**：`random` 场有天花板效应（绝对分 15 分接近该配置的上限），
> 0.82 分差不代表"两者等价"，只代表"在这个难度下分不出更多差别"。不要用它论证 M1 已追平。

## 3. T0.3 耗时剖析（`scripts/iter_profile.py`）

### A. 历史反演（零算力，850 轮全量）

先修一个**日志语义坑**：`history.json` 的 `elapsed` 是在 `run_eval()` / `[snap]` **之前**采样的
（`selfplay.py` 里 `rec` 先构造、eval 后执行），所以第 N 轮的评测/快照耗时会落进 `dt_total(N+1)`。
把成本按正确轮次归位后，用最小二乘分解：

```
dt_total ~ β0 + β1·collect + β2·1[pool 重建] + β3·1[eval/snap]
n = 850，R² = 0.9814
```

| 项 | 系数 | 触发率 | 平均贡献 |
|---|---|---|---|
| 常数项（= update 全链） | **46.18 s/轮** | 100% | 46.18 |
| 采集斜率 | 0.96（无异常传导） | — | 12.58 |
| 进程池重建 | 4.94 s/次 | **80%**（673 次，全是"系统内存 ≥75%"，训练进程树仅 10.3–11.5 GB） | 3.94 |
| eval(40副) + 周期快照 | 66.13 s/次（两列同频不可分离） | 5% | 3.28 |
| **合计** | | | **65.98 ≈ 实测 65.6** |

分段趋势（中位）：iter 1–50 → 57.2 s；400–450 → 63.2 s；800–850 → 62.6 s。
**没有随训练劣化**，说明 22 s 的"神秘开销"一直是同一批固定成本，与内存累积无关。

### B. 实测微基准（24 线程，batch=512，真实检查点）

| 模型 | 参数 | 单步 fwd | 单步 fwd+bwd |
|---|---|---|---|
| `dushan_m1_s3` | 9.84 M | 427 ms | **1290 ms** |
| `dushan_m1_s2`（KL 锚点） | 9.84 M | 425 ms | — |
| `dushan_master`（KLT 教师） | 0.77 M | **44 ms** | — |

换算到 S3 的真实配方（192 局/轮 → 11000 样本，batch 512，epochs 1）：

| update 内部段 | 计算 | 耗时 |
|---|---|---|
| 主模型 fwd+bwd | 22 batch × 1290 ms | **28.4 s** |
| 优势估计的整批前向 | 24 batch 等效 × 427 ms | **10.2 s** |
| KL 锚点整批前向（ref = M1-s2，同规模） | 22 batch × 425 ms | **9.4 s** |
| **合计** | | **48.0 s**（实测常数项 45.77 s，误差 5%） |

另外：

* **KLT 蒸馏的教师前向只要 0.97 s/轮（占 fwd+bwd 的 3.4%）** —— 计划里"单轮 +3%"的估算是准的，
  蒸馏本身**不是**吞吐风险。
* 单局（单线程）：纯引擎 **0.02 s** vs M1 四座 **1.18 s** → **引擎只占采集的 1.5%**，
  采集成本几乎全部是网络推理（12 worker 并行后的 12.6 s）。

### C. 修复清单（按性价比排序）

| # | 项 | 现在 | 修法 | 预期 | 风险 |
|---|---|---|---|---|---|
| 1 | **优势前向 10.2 s** | 更新前用价值头单独跑一遍 11000 样本 | **采集时就顺手把 `value` 一起回传**（采集时模型已经前向过一次，且用的就是同一份权重，**完全等价**） | **−10.2 s** | 无（只多一列 traj 字段） |
| 2 | **KL 锚前向 9.4 s** | 锚是 M1 同规模网络，每步整批前向 | ① 锚前向**每 k 个 batch 算一次**（KL 项按比例缩放）；② 或把锚换成 **master 规模（0.97 s）**；③ 或与 KLT 教师合并（都在"向 master 靠"） | **−8.4 s** | 低（KL 是软约束） |
| 3 | **pool 重建 3.9 s** | 判据是**系统**内存 ≥75%，被桌面常驻 11–14 GB 反复触发（678 次） | 按计划 R6：判据改**训练进程树 RSS ≥ 16 GB**，`--pool-rebuild-every 150 → 250` | **−3.8 s** | 低（有 92% 硬保护兜底） |
| 4 | **eval+snap 3.3 s** | 40 副 × 4 座单进程串行 | 拉长到 `--eval-every 40` + 训练内评测只作健康监控（选点已全交给外部 1200 副配对） | **−2.5 s** | 无（R1 已规定选点不用它） |
| | | | **合计** | **65.6 → ~41 s/轮（+60% 轮次）** | |

> 计划 §4/A7 原目标 48 s/轮（+35%）。**按本诊断可以做到 ~41 s/轮**：
> 多出来的 25 s 主要来自"采集回传 value"与"KL 锚前向降频"这两条，它们是本诊断新发现的。
> 若只做原计划的三条（pool 判据 + 减 eval + 每 worker 快照 8→4），只能到 ~57 s/轮。

## 4. 诊断 → M2-A 配方修正

| 计划条目 | 原方案 | 诊断后修正 |
|---|---|---|
| **A9 辅助头（对手手牌预测）** | "按 M2-0 结论决定是否上" | **不上**。critic 排序相关 0.76、分歧是"软分歧"（平均概率 0.152、80.8% 在前五）、且高价值子集一致率**更高** → 瓶颈不在"看不见对手"，在"排序没对齐"。省下的算力全部投给 A4 |
| **A4 KLT 蒸馏 β 上限** | 0.4 → 0（300 轮） | **维持 0.4**；诊断给出的理由是 M1 在分歧点上"自己也不确定"（置信度 0.371），教师正好提供排序信号。**建议先用 G1（第 300 轮 1200 副）验证，若 vs master 改善 < +1.5 就关 β 重跑**（保留原设计） |
| **A2 探索下限 ε** | 3% → 1% | **维持但不必激进**。探索是治"熵自我熄火"的（D3），不是治"风格差异"的；诊断显示分歧不是"尖峰锁死"（M1 分布反而更平） |
| **A5 对手池** | master 提为一等对手（权重 0.25） | **维持，且建议再提**（0.25 → 0.30）。理由：T0.2 明确显示差距只在"对抗会打牌的对手"时才显现，而对 random 几乎不差 → **要打赢谁就得跟谁多打**（D6） |
| **A3 滚动 KL 锚** | kl_target 0.25 → 0.05 | **维持，并叠加吞吐优化**：锚前向每 k 步算一次（见上表 #2）—— 否则 `kl_coef` 一变小、KL 项贡献变小，但**前向成本不变**，性价比进一步恶化 |
| **A7 吞吐修复** | 目标 48 s/轮 | **目标上修到 ~41 s/轮**，清单换成 §3.C 的四条（新增"采集回传 value"与"KL 锚降频"） |

**一句话**：诊断把 M2-A 的主引擎从"表征/辅助任务"改判为 **"把 master 的取捨排序搬过来"（A4 + A5）**，
并把吞吐预算从 48 s 压到 41 s —— 600 轮的 M2-A 由 8.0 h 缩到 **~6.8 h**。

## 附：诊断过程中的两个方法论修正（供后续复用）

1. **`elapsed` 字段不含 eval/snap** —— 直接按进度行做差会把评测成本归错轮次，且因为
   `eval-every == save-every` 会得出"eval 0.5 s、快照 66 s"这类荒谬结论。
   本脚本已按"eval/snap 落在下一轮、pool 落在本轮"归位。
2. **同频事件不可分离** —— `--eval-every` 与 `--save-every` 相同时，两个指示向量逐位相同，
   lstsq 的最小范数解会把效应平分到两列。已改为自动检测并合并列。
