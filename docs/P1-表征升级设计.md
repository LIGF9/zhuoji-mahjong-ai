# P1 表征升级：设计细化与分阶段验收标准

> 前置结论（来自 P0）：训练内「评测均分」与真实强度的 Spearman 秩相关 ρ ≈ 0，
> s1–s11 十几代累计上万轮大多统计上不可区分 —— **在 0.77M 规模 + 当前表征下，
> 继续堆训练量已不产生可测量增益**。P1 要动的是「网络能看到什么」，这是参数量
> 与训练量之外的独立维度。

---

## 1. 现状盘点：encoder 现在给了网络什么

输入 = 牌面张量 `(15, 27)` + 全局标量 `(70,)`。27 = 3 花色 × 9 点数。

### 1.1 十五个通道（`tiles`）

| 通道 | 内容 | 备注 |
|---|---|---|
| 0 | 自己的手牌是否持有 | 0/1 |
| 1 | 手牌 ≥ 2（对） | |
| 2 | 手牌 ≥ 3（刻） | |
| 3 | 手牌 ≥ 4（杠） | |
| 4 | 手牌张数 × 0.25 | |
| 5–8 | 四家牌河（相对座位），**每张累加 0.25** | ← 严重信息损失 |
| 9–12 | 四家副露 | 杠 1.0 / 其他 0.75 |
| 13 | 该牌可见张数 / 4 | |
| 14 | 该牌剩余张数 / 4 | |

### 1.2 七十维全局标量（`glob`）

| 区间 | 维度 | 内容 |
|---|---|---|
| 0–1 | 2 | 牌墙剩余 / 已摸 占比 |
| 2–4 | 3 | 庄家相对座位、是否自己庄、连庄数 |
| 5–8 | 4 | 庄家相对座位 one-hot |
| 9–12 | 4 | 各家杠数 |
| 13–16 | 4 | 各家副露组数 |
| 17–20 | 4 | 各家牌河长度 |
| 21–24 | 4 | 各家**是否曾经**听牌（`ever_tenpai`） |
| 25–26 | 2 | 手牌总数、是否持豆 |
| 27–28 | 2 | 当前是否听牌、听牌张数 |
| 29–31 | 3 | 幺鸡剩余 / 持有 / 是否首次被打出 |
| 32–34 | 3 | 冲锋鸡归属、是否已产生、责任鸡归属 |
| 35–38 | 4 | 阶段 one-hot + 是否自己回合 |
| 39–65 | 27 | 上一张被打出的牌 one-hot |
| 66–69 | 4 | 该出牌者的相对座位 |

### 1.3 五个缺口

1. **牌河无时序（最严重）**。`discards[p]` 本来是有序列表，编码时被压成
   「累加 0.25/张」，**「谁在第几巡打了什么」被彻底抹掉**。而读牌的核心正是
   「上家最近打了什么」「这张牌是不是他刚打过」——时序一丢，危险度判断基本
   无从谈起。
2. **没有危险度**。没有现物/筋牌/生牌的区分，没有「打出这张牌对谁有风险」。
   这是麻将 AI 最值钱的一类特征。
3. **对手状态是「曾经」而非「现在」**。`ever_tenpai` 只记录历史上是否听过，
   不反映当下。
4. **番型潜力缺失**。只有「是否听牌」，没有「距离多大番还有多远」、「哪些
   役种还活着」。独山番型体系（豆、鸡、清一色、七对、大对子…）差异极大，
   不知道目标番型就没法做收益/风险的权衡。
5. **巡目与情境缺失**。没有显式巡目、没有阶段划分、没有黄庄紧迫度、没有包鸡
   风险敞口。

> **红线：所有新特征只能来自公开信息** —— 自己的手牌、四家的副露、四家的牌河、
> 牌墙剩余等公共状态。**不得读取任何对手的手牌**。对手状态一律用「从公开信息
> 推断的启发式」表示，并在文档里写清公式，避免把作弊当成特征工程。

## 2. 设计总览：拆成三个独立可验收的特征包

不做「一次性改一大堆特征」——那样即使涨了分也不知道是谁的功劳，跌了也排不掉
嫌疑。拆成三个**互不依赖**的包，每个单独实现、单独消融、单独验收：

| 包 | 内容 | 主要改动 | 预计增益类型 |
|---|---|---|---|
| **P1a** | 牌河时序 | `tiles` | 读牌能力、防守判断 |
| **P1b** | 危险度与对手状态 | `tiles` + `glob` | 点炮率下降 |
| **P1c** | 番型潜力与巡目情境 | `glob` | 番型选择、包鸡规避 |

三个包都通过验收后再合并，进入阶段 3 长训练。

### 维度规划（最终目标）

| 项 | 现状 | P1a | P1b | P1c | 合计 |
|---|---|---|---|---|---|
| `NUM_CHANNELS` | 15 | +12 | +4 | — | **31** |
| `GLOBAL_DIM` | 70 | — | +10 | +18 | **98** |

## 3. P1a：牌河时序（通道 15–26）

**做法**：给每一家额外提供「最近第 1 / 第 2 / 第 3 张出牌」三个独立通道，
取代原先「全部累加成一个通道」的信息压扁。累加通道（5–8）保留，作为
「该家历史总体倾向」的粗粒度补充。

| 通道 | 内容 |
|---|---|
| 15–18 | 各家牌河**最近第 1 张**（one-hot，座位相对） |
| 19–22 | 各家牌河**最近第 2 张** |
| 23–26 | 各家牌河**最近第 3 张** |

**实现要点**

- 牌河不足 3 张时对应通道全 0（不填充、不重复计）。
- 只取「最近 3 张」而非整条牌河：真正有信息量的是近期行为，早期出牌已被累加
  通道概括；同时控制通道数，避免 stem 卷积成本失控。
- 三帧按**时间倒序**排列（第 1 张 = 最近）。

**为什么选 3 帧而不是 6 帧**：麻将读牌的注意力窗口通常在 2–4 巡；通道数从 15 涨
到 27 已让 stem 卷积（15→C 变成 27→C）成本近翻倍，而 ResBlock 部分不变，整体
耗时增幅可控。先做 3 帧验证方向，确认有效再考虑加深。

**预期可测量的效果**：点炮率（`deal_in_rate`）下降，或同样点炮率下自摸率上升。

## 4. P1b：危险度与对手状态（通道 27–30 + glob 70–81）

### 4.1 四个危险度通道（`tiles` 天然对齐 27 张牌）

| 通道 | 名称 | 定义 |
|---|---|---|
| 27 | `safety_genbutsu` | 现物安全度 = (已打出过该牌的玩家数) / 3 |
| 28 | `safety_suji` | 筋牌安全度（简化） = 同花色 ±3 范围内可见张数 / 4 |
| 29 | `danger_live` | 生牌危险度 = 1 − 可见张数/4（完全不可见 = 1） |
| 30 | `opp_potential` | 对手潜在需求 = 对手副露花色 / 牌河密集花色的加权指示 |

这四个都是「对每张牌的风险评估」，与 `tiles` 的 27 列天然对齐，卷积核可以直接
把「手牌里有什么」和「打出去有多危险」做局部关联。

> `safety_suji` 先做简化版：真正的筋牌规则要考虑「是否鸣牌后放铳」等细节，
> 首版只统计同花色相邻可见情况，作为危险度的一阶近似。

### 4.2 对手状态标量（`glob` 70–81，12 维）

| 区间 | 维度 | 内容 | 公式（仅用公开信息） |
|---|---|---|---|
| 70–73 | 4 | 各家**估计向听数下界** / 6 | `lb = clamp(4 − 副露组数 − 牌河中成对/连续组估计, 0, 6)` |
| 74–77 | 4 | 各家**已亮明鸡数** / 4 | 来自 `game.claimed_ji` 公开记录 |
| 78–81 | 4 | 各家**当下听牌置信**（启发式） | `conf = f(副露组数, 巡目, 牌河是否收窄)`，非真值 |

**必须写清这是启发式**：`lb` 和 `conf` 都不是真值，是从公开信息推出的有噪声估计。
好处是：即使估计不准，卷积核也能学到「这个信号不可靠时该打折」。但公式要固定、
可复现，不能引入未来信息（例如不能用「对手最终是否听牌」回填）。

## 5. P1c：番型潜力与巡目情境（`glob` 82–97，16 维）

| 区间 | 维度 | 内容 |
|---|---|---|
| 82 | 1 | 巡目 / 12（`turn = (108 − wall_left − 开局手牌) / 4`） |
| 83–85 | 3 | 阶段 one-hot（序盘 ≤4 巡 / 中盘 5–9 / 终盘 ≥10） |
| 86–93 | 8 | 番型可行性标志：豆 / 清一色 / 七对 / 大对子 / 平胡 / 将对 / 门前清 / 青龙 |
| 94 | 1 | 自己当前可达**最大番型值** / 30 |
| 95 | 1 | **黄庄紧迫度** = (1 − wall_left/108) × (自己未听牌) |
| 96 | 1 | **包鸡风险敞口** = (自己未听牌) × (他家已亮明鸡数 > 0) |
| 97 | 1 | 自己手牌**鸡价值**（幺鸡数 + 已成刻的鸡）/ 4 |

番型可行性用 `zhuoji/fan.py` 已有的判定函数计算「离该役种的张数距离」，归一化后
作为连续值，而不是简单的 0/1 布尔（布尔丢失了「差一步」和「差很远」的区别）。

**为什么这组特征对独山特别重要**：独山有包鸡（未听牌者赔已亮明鸡）与责任鸡溢价，
「我是否听牌」的收益不对称性远高于普通麻将。`95`/`96` 这两个标量直接把这种
不对称性摆到网络面前。

## 7. 分阶段验收标准

**通用评测口径（P0 建立，不得更改）**

- 用 `scripts/duel_stats.py` 或 `scripts/score_checkpoints.py`，**复式 4 座位轮换**；
- 3 个对手：现任大师 `dushan_big_s11` + 教师·先听 + 均衡教师；
- 报告**逐副配对净分差 ± 95% CI**，只看区间是否跨 0；
- 参考量级（来自 `tests/test_selection.py` 已验证）：2400 副时 CI ≈ ±0.29；
  1200 副 ≈ ±0.41；600 副 ≈ ±0.58。

> **禁止**用训练内「评测均分」判定成败 —— P0 已证明它与真实强度秩相关 ≈ 0。

---

### 阶段 0 · 实现与单测（预计 0.5 h）

| 项 | 通过标准 |
|---|---|
| 维度 | `NUM_CHANNELS_V2 == 31`，`GLOBAL_DIM_V2 == 98`，`Observation` 形状断言 |
| 取值范围 | 所有通道 ∈ [0, 1]；所有标量 ∈ [0, 1]（或按设计的上界归一化） |
| **视角不变性** | 同一局面下，四个座位各自编码，其「相对座位」维度应互为循环置换；用固定种子随机 200 局断言 |
| **无信息泄漏** | 断言 v2 编码过程中未触碰任何对手手牌（用「篡改对手手牌不应改变编码」的测试） |
| 空局/边界 | 牌河为空、牌河只有 1 张、刚开局 13 张等边界不报错且通道全 0 正确 |
| 回归 | `smoke_test` / `test_encoder` / `test_rob_kong` / `test_dushan` 全绿 |

**阶段 0 不通过则不进阶段 1。**

---

### 阶段 1 · BC 重生成与行为克隆基线（预计 1.5 h）

目的：确认新表征**至少能学会模仿教师**，不引入退化。

| 项 | 通过标准 |
|---|---|
| 数据 | `data/bc_v2.npz` 生成成功，样本量 ≥ 旧 BC 的 95% |
| 训练 | BC 训练收敛（val_loss 曲线无异常） |
| **不退化** | 验证集各头准确率相对 v1 BC **下降 ≤ 0.5 个百分点** |
| 分布一致 | 与教师策略的 KL ≤ v1 BC 的 1.1 倍 |

若这里就明显退化（准确率掉 > 1pp），说明新特征实现有错（最可能是归一化或视角
搞反），**回到阶段 0 排查，不要带着错误特征往下跑**。

---

### 阶段 2 · 单变量消融（预计 5 h，三包各约 1.5 h）

每个包单独开一版，**同一 BC 起点、同一超参、同一 seed、固定 400 轮**：

| 项 | 设定 |
|---|---|
| 训练 | 400 轮，`--games-per-iter 96 --batch 512`，seed 固定 |
| 评测 | ≥ **1200 副**复式对位（CI ≈ ±0.41），对手同通用口径 |
| **采纳门槛** | 配对净分差 **≥ +0.40 分** 且 **95% CI 下界 > 0** |
| **否决门槛** | 净分差 ≤ 0，或 CI 上界 < +0.20 → 该包不采纳 |
| 待定区 | 落在 +0.20 ~ +0.40 且 CI 跨 0 → 加测到 2400 副再判 |

**三个包各自独立判定**，互不牵制。否决的包要写进负结果记录（避免以后重复试）。

---

### 阶段 3 · 合并特征 + 长训练（预计 8 h）

采纳的包合并，从新 BC 出发训练 **2–3 代**（每代 600–1000 轮），逐代用 P0 标尺选点
（`--select guard --save-every 50`，并在训练外用 `score_checkpoints.py` 复核）。

| 项 | 通过标准 |
|---|---|
| 终选评测 | 对 `dushan_big_s11` **≥ 2400 副** |
| **晋升门槛** | 配对净分差 **≥ +0.50 分** 且 **95% CI 下界 > 0** |
| 副作用检查 | 点炮率不显著上升；黄庄率无异常；冲鸡率/包鸡率变化有解释 |

通过 → 晋升为新大师（备份旧 `dushan_master.pt`）；不通过 → 保留 s11，记录负结果。

---

### 阶段 4 · 稳健性复核（预计 2 h）

P0 已发现「换一个对手场，冠军就换人」（两场 Spearman ρ=0.615）。所以任何晋升
结论都必须做换场复核：

| 项 | 通过标准 |
|---|---|
| 换场 A | 换不同对手组合 + 不同 seed 重测 ≥ 1200 副，**方向一致**（仍为正） |
| 换场 B | 换教师权重风格重测 ≥ 1200 副，**不出现显著反向** |
| 判定 | 两个场都通过 → 结论稳健；只有原始场通过 → 判定为「未确认」，不得晋升 |

## 8. 时间与算力预算

| 阶段 | 14700K（估） | 当前 Tiger Lake |
|---|---|---|
| 0 实现与单测 | 0.5 h | 1 h |
| 1 BC 重生成 + 克隆 | 1.5 h | 4 h |
| 2 消融（3 包） | 5 h | 15 h |
| 3 合并长训练 | 8 h | 24 h |
| 4 稳健性复核 | 2 h | 6 h |
| **合计** | **≈ 17 h** | **≈ 50 h** |

> 通道数 15 → 31 会让 stem 卷积成本近翻倍，整体每轮耗时预计上升 15–30%
> （ResBlock 占大头，不受通道数影响）。上面的预算已含这部分。
> 参数量在 P1 阶段保持 0.77M 不变 —— **这一阶段不放大网络**，避免把「表征收益」
> 和「容量收益」混在一起说不清。

## 9. 反 winner's curse 纪律（硬约束）

P0 实测：winner's curse 的代价约 **0.5–0.7 分**（评测均分历史最高的 s6 实际排第 6）。
所以 P1 全程遵守：

1. **门槛事先写死**（本文档即前置声明），不得看到结果再调门槛；
2. **一次只测一个假设**，不并行试多版挑最好的；
3. **所有负结果都记录**（写进 `reports/` 与工作日志），避免重复试错；
4. **晋升必须过换场复核**，原始场单独通过不算通过；
5. **样本量按效应量定**：想检出 +0.4 分就要 ≥1200 副，想检出 +0.5 分就要 ≥2400 副；
   不要用 200–600 副的结论下判断（P0 已证明那个量级下名次不可信）。

## 10. 与后续阶段的关系

- **P1 不放大网络** → 参数量、训练量都不变，唯一变量是「表征」；
- **P2（GRP + Oracle 引导 + λ-return）** 在 P1 定稿的表征上做，同样保持其他变量不变；
- **P3 才放大规模**（5.1M → 10M）并提高 `--games-per-iter`；
- 只有 P1/P2 各自被证明有效，P3 的算力投入才有意义 —— 否则只是把 P0 那条
  「打平曲线」整体平移。
