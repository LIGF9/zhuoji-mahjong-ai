## 0. 执行摘要

**现状**：`exit_p48`（v3，9.85M 参数）对冻结基线显著更强——贪心 vs master 贪心 `+5.143±0.314`、贪心 vs master+N32 `+1.478±0.297`、双侧 N32 `+0.679±0.309 (p=.0282)`；独立旁证方向同向但分辨率不足。**但它的推理成本是老模型的 9~13 倍**（离线 N32 约 2.1 s/决策）。2026-11-10 修真档后按编码器版本自动改走 torch-MPS，线上「冠军 + 搜索」实测 `search128` **1.76 s** / `search32` **2.64 s**，**已可用**；E-SLIM 的定位因此从「可用性的前提」降为「进一步降本的杠杆」。历史「28.4 s/决策」是 ORT-CoreML 后端的测量，该后端已不再用于 v3 冠军。

**成本诊断（实测，非估算）**：一次 N32 搜索决策中，神经网络前向累计占 **94–98%**，Rust 搜索骨架 + 结算 + 编码 + 聚合仅 13 / 59 ms（2–6%）。两档搜索的节点数几乎相同（约 1 万 states），9.2× 差距**全部来自网络每状态前向**（v3 178.9 µs vs v1 16.9 µs @B=256）。后端（ORT / CoreML / MPS）均已试过，ORT 更慢、v3 CoreML 被切 65 分区、MPS 吞吐与 batch 无关。⇒ **「再用 Rust 加速」理论上限只有 2–6%，不是有效杠杆。**

**因此本计划的核心判断**：

| 目标 | 有效杠杆 | 无效杠杆 |
|---|---|---|
| 进一步降低 P48 搜索档成本（**可用性已由后端切换解决**） | **压缩网络（方案 E）+ CoreML fp16 算子融合** | Rust 重写、换 `ply/n_det`、调 batch、**INT8/INT4 量化**（MPS 无收益） |
| 让结论更可信 | **预锁 δ/TOST + seed 块 bootstrap + 多对手池** | 同池配对（实测 `ρ≈0`，不降方差）、重跑已耗池、单局重采 bootstrap |
| 再提升棋力 | 更强的教师 / 目标对齐的训练（高成本、改配方）/ Q 值锚定微调 | 在同配方上继续训练（早停已证边际增益 < 0.22 分） |

**推荐路线（需批准）**：`E-STAT 评测协议升级 + E-ALIGN 目标对齐审计`（均零算力，作为门禁）→ `P0 E-SLIM 分级蒸馏瘦身（含教师 Q 熵加权 + CoreML fp16 打包）` → `P1 E-POOL 多对手池` → 视结果决定 `E-ANCHOR Q 值锚定微调` 或 `P2 教师升级 / 奖励塑形`。`P3 league / 大规模自对弈 RL / Suphx 式 RL` 在单机条件下不可行，仅登记不排期。

> **调研补正（后台前沿调研回传后修订，2026-11-10 01:36）**：初稿把「量化 / 算子融合」整体列为不建议，**这一判断需拆分修正**——Apple Silicon AMX 无 int8 matmul 加速、M3 Ultra 上 CoreML 全量化级别均未观察到推理加速（**INT8/INT4 确实无效**），但 **CoreML fp16 转换本身的算子融合 / Metal kernel 有公开实测 −39% 推理耗时**（UNet 87.6 ms → 53.4 ms），应与方案 E 打包验证。另补入三个初稿缺失的低成本项：**E-STAT**（TOST 非劣 / δ 预锁 / seed 块 cluster bootstrap / BH-FDR，零训练算力）、**E-ANCHOR**（冻结 P48 或教师 Q 作锚做 value-regression 微调，TanyaoDojo 实测配对 `+1.75, z=2.58`，零新增标注）、以及 E-SLIM 的**按教师 Q 熵过采样 contested states**。详见 2.5 / 3.9 / 3.10。

## 2. 前沿方法与知名系统调研（公开来源）

### 2.1 Suphx（Microsoft Research Asia, 2020）

论文 [arXiv:2003.13590](https://arxiv.org/abs/2003.13590)；中文技术拆解见 [机器之心/澎湃](https://m.thepaper.cn/newsDetail_forward_6861899)、[alphaXiv 中文摘要](https://www.alphaxiv.org/zh/abs/2003.13590)。

- **流程**：① 人类职业牌谱监督学习（5 个 CNN：discard / Riichi / Chow / Pong / Kong，50 残差块，含 look-ahead 特征）→ ② 分布式自对弈策略梯度 RL（重要性采样处理轨迹陈旧 + 动态熵正则）→ ③ 三项专用技术 → ④ Tenhou 实战 5000+ 局。
- **三项技术**：
  - **全局奖励预测**：GRU 根据当前与历史回合预测整场最终奖励，用 `Φ(x_k) − Φ(x_{k−1})` 作为逐回合细粒度奖励，解决「一局分数不等于最终名次」的信用分配问题；消融显示 RL-1 显著优于 RL-basic，且让模型学会防守。
  - **Oracle Guiding**：先用完美信息（含对手手牌与牌墙）训练 oracle，再用 Bernoulli dropout 逐步衰减完美特征，平滑过渡到正常信息策略，加速收敛。
  - **pMCPA**：每局开局采样隐藏信息生成 K 条 rollout，用重要性采样微调离线策略，适应本局手牌；适应版对非适应版 **66% 胜率**（固定初始手牌 + 10 万轨迹测试）。
- **结果与代价**：Tenhou 稳定段位 8.74 段、放铳率 10.06%，超越 99.9% 人类；离线评估约 **100 万局**稳定段位（stable rank 取 1000 次抽样 × 800K 局的 IQR）；每个 agent **约 1.5M 局自对弈、44 GPU（4 Titan XP 参数服务器 + 40 K80 自对弈）× 2 天**，Suphx≈RL-2 约 2.5M 局；单 agent 离线评估另耗 **20 K80 × 2 天**。SL 阶段 5 个模型分别用 15M/5M/10M/10M/4M 样本，discard 测试 acc 76.7%。论文自承 **pMCPA 计算开销过大、限制线上部署**——每回合需约 **100K 条 rollout**，且论文脚注明确 **天凤线上实战并未启用 pMCPA**（adapted vs non-adapted 的 66% 胜率只是固定初始手牌的离线测试）。
- **对本项目**：全局奖励预测 / 名次辅助头与「本项目用零和分差而用户关心名次」的问题直接相关（见 3.4）；Oracle Guiding 与 pMCPA 都**改动主链配方且算力远超单机**，本周期明确不排。

### 2.2 Mortal / Mortal-S42（开源日麻 AI）

训练管线见 [DeepWiki: Mortal Training Pipeline](https://deepwiki.com/Equim-chan/Mortal/3.3-training-pipeline)；模型卡见 [Mortal-S42 (HuggingFace)](https://huggingface.co/buckets/ms903/Mortal-S42-bucket/tree/README.md?code=true)。

- **架构**：Brain（ResNet，192ch×40 blocks）+ dueling DQN 头；`libriichi`（Rust）负责状态管理与批量推理；**1v3 评测**（`games_per_iter=2000, iters=500`）。
- **训练**：MJAI 牌谱 → `RewardCalculator` 用 **GRP（Game Result Prediction）模型**给出「期望点数变化」作为奖励 → DQN（Monte Carlo 回报、MSE）+ **CQL 保守正则**（离线训练时抑制未见动作的 Q 外推）+ **最终名次预测辅助任务**；分离线（历史牌谱，启用 CQL）与在线（客户端自对弈，不启用 CQL）两种模式。
- **Mortal-S42**：10,835,631 参数、192ch×40 res、dueling DQN；训练谱系 `stable 380k → H20k → S42.8k`，Base 约 110 万局天凤凤凰桌牌谱，Phase H 36 万局，Phase S 27 万局（高段雀魂 + 天凤复盘），**Phase S 用离线 CQL + 名次辅助目标**。
- **公开强度与协议细节（补充）**：Mortal 4.1c 对 akochan 平均顺位点 `+1.89`、放铳率 −1.78%，但对自家 1.0 版只有 `+0.25`、对 3.1 版 `+0.33` ⇒ **改版增益很小**。Mortal-S42 用 reciprocal 1v3、相同 seed 块、四座轮转、**每方向 1 万局 / 每比较 2 万局**，配对 95% 区间按 **seed 块差值**计算；`S42.8k−H20k = −0.0167 [−0.0422,+0.0088]`（过闸门但无显著增益）。仓库明确警告「历史 bootstrap 重采的是单个 hanchan 而非镜像 seed 组，**不能当作 seed 组聚类证据**」——本项目按 seed 聚合的做法是对的。
- **Mortal FAQ 的关键警告（直接影响蒸馏）**：Q 优化目标是 `Φ_{k+1}−Φ_k`，**「除最优动作外其它动作的 Q 可能明显不准，只是训练时用来决定探索偏好」**；Mortal-S42 模型卡亦注明「Q-values 是相对动作分数，**不是校准过的胜率**」。⇒ 本项目若把已有 1.6M 行**全动作 Q 向量**直接当蒸馏目标，必须处理非最优动作 Q 的未校准性（见 2.5 的 Q 熵加权）。
- **对本项目**：① 我们的 ExIt/DAgger 是「教师全 Q 监督」，Mortal 是「离线 Q 学习 + CQL」，两者数据需求不同，但**CQL 思路可作为「若改用离线 RL 时的防外推护栏」**；② 名次预测辅助头与 Suphx 的全局奖励预测指向同一问题；③ 10.8M 参数与 P48 的 9.85M 同量级，说明「大网」在麻将里是常态，**但它们的线上部署也依赖 Rust 批量引擎而非搜索**——反衬方案 E 的必要性；④ 本项目教师 Q 来自搜索实测标注、非 bootstrap 外推 ⇒ **天然规避了标准离线 RL 的 OOD 过估计问题**，不必引入 CQL/IQL。

### 2.3 TanyaoDojo（2026，最重要的负面教训）

仓库 README 见 [HuggingFace: Twu31/TanyaoDojo](https://huggingface.co/Twu31/TanyaoDojo/blame/2ade17f4c2dd3e11acfa00ce18ffd74425cb5430/README.md)。

- **基线**：BC on 10 年牌谱，`256ch×10blk / 12.4M` 参数，`avg_pt = −4.66 ± 0.535`，**100k 局里程碑测量**（16.0M 决策，零回退）；小模型 `192ch×8blk / 5.3M` 为 `−8.87 ± 2.70`（4k 局）⇒ **容量缩小确实会掉强度**（这正是方案 E 的主要风险）。
- **公开的四次连续 RL 负结果**：`rl_oracle_800m`（oracle-critic PPO league，0.8B steps）为 `−8.38 ± 2.65`，比基线**弱 3.2 分以上**，且训练越久越差；critic 拟合误差改善 100×（0.102→0.001）反而更糟。
- **作者 2026-08-23 更正结论**：**根因不是「oracle critic 不迁移」，而是训练目标 ≠ 评测目标**。四次 RL 都用 `round_mode="single"`（单局即终止）且奖励是麻将原始点数转移，而竞技场按整场 **placement points [90, 45, 0, −135]** 计名次；单局点数最大化者不知道「第四名有额外惩罚」，因此会过度进攻。修正为整场名次对齐奖励后，首个结果 `−4.88 ± 0.81`，与基线**统计持平**（退化消失，但仍无显著提升）。
- **对本项目（最高警示价值）**：本项目统计量是 `deltas[cand_seat] − mean(其余三家)`（零和分差），而 §4 目标与用户线上体感都更接近「相对名次」。**任何新的 RL / 奖励塑形实验，必须先在文档里写死「训练奖励与评测统计量的对齐证明」**，否则极可能重演「训练更久、离线拟合更好、实战更差」。此外 1B steps 只换来统计持平 ⇒ **不要期待靠 RL 微调获得大幅提升**。

### 2.4 AlphaStar League / PSRO 与非传递性

[DeepMind: AlphaStar Grandmaster](https://deepmind.com/blog/article/AlphaStar-Grandmaster-level-in-StarCraft-II-using-multi-agent-reinforcement-learning)、[NeurIPS 2023: ROA-Star](https://proceedings.neurips.cc/paper_files/paper/2023/file/94796017d01c5a171bdac520c199d9ed-Paper-Conference.pdf)、[AlphaStar Unplugged 概览](https://aiwiki.ai/wiki/alphastar)。

- 自我对弈会「追尾巴」（石头剪刀布循环）；fictitious self-play 不足以解决 ⇒ League：1 个 main agent + 1 个 main exploiter + 2 个 league exploiters，保留历史策略多样性，最终按 Nash 分布采样。
- 代价：AlphaStar 联赛阶段 14 天 × 每 agent 最高 200 年模拟对局，256 个 TPU v3 核 + 4100 CPU；ROA-Star 用 64×V100 + 4600 CPU 改进后才显著更强。**远超本项目单机**。
- AlphaStar Unplugged（2023）证明**离线 RL**（280 万局数据集）可训练出 90% 胜率击败 SL 基线——但需要海量固定数据集。
- **对本项目**：① 现协议 1v3 + 四座旋转是完备 duplicate（`C(4,1)=4`），但结论只对单一冻结基线成立；② **低成本补法是「多对手池评测」而非 league 训练**（见 3.3）；③ 非传递性意味着「对 master 强」不能推出「总体最强」，措辞必须限定。

### 2.5 模型压缩（蒸馏 / 剪枝 / 量化）

综述见 [Knowledge Distillation](https://aipinnacle.org/ai-glossary/distillation)、[压缩/剪枝/量化对比](https://www.easydeeplearn.com/study/deep-learning/compression-interpretability)、[AI Wiki: Knowledge Distillation](https://ai.miraheze.org/wiki/Knowledge_distillation)。

- **蒸馏**：学生拟合教师的高温 soft targets（`L = α·CE + (1−α)·T²·KL`），通常恢复 **90–98%** 的师生差距，可小 5–10×；但存在 **capacity gap**——师生容量差过大时学生学不动，需「teacher assistant」中间尺寸过渡；且会**继承教师盲点**。教师 logits 可预计算缓存以省训练开销。
- **结构化剪枝**（整通道/整块移除）才有真实延迟收益；非结构化剪枝只省内存。**量化**（PTQ INT8 约 1.5–2×、INT4 2–3×）最快但精度损失需业务集验证；三者可叠加（剪枝→蒸馏恢复→量化）。
- **对本项目**：P48 → ≤1.0M 是 **12.8× 压缩**，远超常规蒸馏的 5–10×，一次到位很可能触发 capacity gap ⇒ **建议分两级（先 3M 级 teacher assistant，再 ≤1M）**。另 §6.67 记录 ONNX `max|Δ|=2.6e-5`、CoreML `1.2e-3` 已足以改变 argmax ⇒ **任何改变数值精度的方案都须逐位验证或重跑全池**。
- **Apple Silicon 的量化负面证据（强，务必据此拆分判断）**：AMX 只支持 fp16/fp32、**无 int8 matmul 加速**；`mps-bitsandbytes` 实测 INT8 缓存 0.98 ms vs FP16 1.08 ms（几乎无提速），不缓存 9.65 ms（慢 10×）；M3 Ultra 上 CoreML 的 INT8/6/4/2-bit **任何量化级别都没观察到推理加速**（统一内存 800GB/s 下 compute-bound 而非带宽-bound）；arXiv:2511.05502 亦指出 PyTorch MPS 的 INT4/INT8 属实验性、不是实用部署选项。⇒ **INT8/INT4 量化在本机明确无效**。但**唯一实测有效的是 CoreML 转换本身（算子融合 / Metal kernel）：UNet 87.6 ms → 53.4 ms，−39%**，NE 原生货币是 fp16 ⇒ **应作为 E-SLIM 的打包项验证，而不是与量化一起否掉**（修正初稿判断）。来源：arXiv:2605.16259、arXiv:2511.05502、mps-bitsandbytes、WWDC2024-10160。
- **蒸馏教师信号的正确格式（对本项目直接可用）**：教师信号有 argmax(one-hot CE) / **Q-values（|A| 个值，平方误差，保留「完整排序 + 尺度」，最适合后续恢复 value-based 学生）** / 动作 logits(CE) / 搜索访问次数(CE) 四类；温度 τ 建议 3–5。本项目已有**全 28 槽教师 Q 向量**，天然属于第二类。高杠杆低成本做法：训练好的策略在多数状态近乎确定，均匀采样会把算力浪费在「照抄众数」就能匹配的状态上 ⇒ **按教师 Q 熵加权 / 过采样 contested states，并记录熵分布**（来源：scixa policy distillation 教师信号表、arXiv:2610.34791 的 Q 蒸馏小网实例）。**注意 Mortal FAQ 的未校准警告**：非最优动作 Q 故意不校准，直接平方误差拟合全 Q 会把噪声当信号 ⇒ 需 Q 熵加权或只对 top-k 动作加权。
- **容量风险的具体量级（KataGo, arXiv:1902.10565）**：渐进式网络 `(b,c)=(6,96)→(10,128)→(15,192)→(20,256)`，19 天 / 26–28 V100 / 约 1.4 GPU-年，相对 ELF/AlphaZero 约 50× 算力削减；但 **Table 7 在等 1600 节点下小网显著更弱**：b6c96 `−1276`、b10c128 `−850`、b15c192 `−329`、b20c256 `+76` Elo（极差 1352）。caveat：等节点 ≠ 等 GPU 成本（查询成本约 `b·c²`），论文未给等算力 H2H。⇒ **「10× 压缩保住棋力」在棋牌上无保证**，E-SLIM 必须用 TOST 非劣判据而非「p>0.05 即持平」。KataGo 的 `playout cap randomization`（p=0.25 回合做 full search 且只有这些回合记入训练，其余 75% 用 fast search，去掉后 Elo 1329→1242、训练时间 1.37×）另支持「价值/策略算力解耦」，可作为 3.10 之后的主链内采样候选。

### 2.6 评测方法学

- Suphx 离线评估约 100 万局稳定段位；Mortal 1v3 `2000 局/轮 × 500 轮`；TanyaoDojo 裁决线 **12k 局 = 3k 牌墙**（"nothing gets claimed without the 12k double-segment protocol"）、里程碑 100k 局。
- IJCAI 麻将赛用 Swiss + 同一牌墙 24 座位排列（四个玩家都不同）；本项目 1v3 下 `C(4,1)=4` 已完备。
- 文献明确批评「不做 duplicate 会受高方差影响」，并要求 **seed-clustered SE**、多重比较校正、TOST 等价检验与功效分析。本项目现行按 seed 聚合 + 预登记判据已达标；**短板是多重比较与跨对手外部效度**，不是样本量。
- **可引用的量化证据（补充）**：MDPI *Algorithms* 2023, 16(5):235 记录 IJCAI 麻将赛用 Swiss + duplicate，**同一牌墙打 24 局（全部座位排列）求和为一个 duplicate game**；4 个相同 bot 对打 4000 局时**座位效应达 0.13，大于待测效应**（⇒ 四座旋转是有效性前提）；另有 60 轮 PPO / 6 万局自对局后 RL **未超过老师**（`−0.021±0.042`，全在 CI 内）。arXiv:2610.34791 用 1000 局 seed-clustered SE `2.511±0.028`，并**在看结果前固定 TOST margin ±0.10 名次**（≈ between-block SD 0.14），得 `p=6e-4` 的「等价」结论；明确「100 配对局只能分辨 ≈0.25 名次（50% 功效）/ 0.34（80%），故 `+0.02±0.12` 应读作不可分辨、不是零」。
- **对旁证的直接换算**：本项目 E-SIDE `SE=0.665`，按 `SE ∝ 1/√n` 压到主池 `SE=0.309` 需约 **`(0.665/0.309)² ≈ 4.6×`（≈550 seed）**，压到 0.20 需 ≈11×。⇒ 与其单纯堆 seed（成本主要来自 v3 搜索 2.1 s/步），更划算的是**预锁 δ + TOST + seed 块 cluster bootstrap + per-decision 诊断量做早期筛选**（见 3.9）。统计实践补充：Bouthillier MLSys 2021 指出 seed/超参方差与测试集方差同量级、真差 0.5 时 25 seeds 才 83% 检出；20 次比较宜用 BH-FDR；连续窥视/早停宜用 e-values / anytime-valid 方法。

### 3.1 【P0 · 推荐】E-SLIM：学生瘦身 / 分级蒸馏（方案 E 落地）

| 项 | 理由 |
|---|---|
| INT8/INT4 量化 | Apple Silicon AMX 无 int8 matmul 加速、M3 Ultra 上 CoreML 全量化级别零加速（2.5 节）⇒ **本机明确无效**；且 §6.67 数值残差足以改 argmax，验证需重跑全池，**净收益为负** |
| **CoreML fp16 转换（算子融合）** | **不是量化**，公开实测 −39% 推理耗时 ⇒ **建议打包进 E-SLIM 验证**（见 3.1 步骤⑥），但须逐位前向校验 |
| Rust 重写推理 | 前向占 94–98%，Rust 理论上限 2–6%；ORT/CoreML/MPS 均已试过 |
| 冠军加搜索同池 A/B | 附录 B.6 已剖析：同池逐 seed `ρ=+0.0009`，**配对不降方差**；500 seed 花 22.7 h 得到 `SE=0.429 / p≈.062`，与已有跨实验相减精度完全相同 ⇒ 花钱买回同一句话。且 §4 主目标已收口，答案大概率「不开搜索」 |

### 3.9 【P1 · 新增，零算力】E-STAT：评测协议升级（后续所有判据的前置门禁）

| 项 | 内容 |
|---|---|
| 回答什么 | 把「`p=.1923` 分辨率不足」变成可判定的**等价 / 非劣 / 优势**，并防多重比较与 winner's curse |
| 改配方 | 否（纯统计协议，零 GPU、零新对局） |
| 步骤 | ① **看结果前锁死**最小决策效应 δ 与 TOST 等价 margin（参考 arXiv:2610.34791 固定 ±0.10 名次 ≈ between-block SD 0.14；本项目按 σ=6.915 与业务可接受分差定 δ，写死后不改）；② 把 bootstrap 重采单位从「单局」改为 **seed 块 cluster bootstrap**（Mortal-S42 明确警告单局重采不能当作 seed 组聚类证据）；③ 多片比较用 **BH-FDR** 控多重比较，预注册 1 个主比较、其余标探索性；④ 引入 **per-decision 诊断量**（弃牌/响应一致率类）做 4k 小样本早期筛选——TanyaoDojo 实测 4k 局强度筛选全在噪声内，而 per-decision 量能立刻发现回退；⑤ 连续窥视/早停改用 anytime-valid / e-values；⑥ 报告 seed 分布而非最大值 |
| 成本 | **≈2–4 h，零 GPU**（在已有 2000 / 480 行 jsonl 上重算） |
| 预期收益 | 不提升棋力；把「不可分辨」与「等价」分开、防止 ns 被误写成「无差异 / 到顶」、让 E-SLIM 的 TOST 判据真正可执行。按 `SE∝1/√n`，跨池旁证若想达到主池 `SE=0.309` 需 ≈550 seed（4.6× 成本）⇒ 可据此判断「单纯加 seed」是否划算 |
| 判据（看前锁死） | δ 与 margin 必须在跑任何新比较**之前**写入文档；交付物是一份协议文档 + 对既有 3 个实验的**复算**（复算不得改原结论，只标注新口径下的判定类别） |
| 风险 | δ / margin 事后调整即失效；per-decision 诊断量与棋力的相关性需单独验证，**不得替代强度判定** |
| 优先级 | **P1，与 E-ALIGN 并列门禁，排在任何新判定之前** |

### 3.10 【P1/P2 · 新增，零新增标注】E-ANCHOR：Q 值锚定微调防漂移

| 项 | 内容 |
|---|---|
| 回答什么 | 用冻结的 P48（或已有教师 Q）作锚做 value-regression 微调，能否在不重标教师的前提下再挤出增益 |
| 改配方 | **边界情况**：属「后训练微调」，不改教师 / 目标 / 评估口径，但改训练损失 ⇒ **需用户裁定是否算改主链**，未裁定前不排期 |
| 步骤 | ① 以 P48 为 reference，加 KL / Q-anchor 正则（权重 0.1–0.2，参考 TanyaoDojo 用 0.2）做 value-regression 微调；② **必须先通过 E-ALIGN 与 E-STAT 两道门禁**；③ 锚必须选「好 ckpt」而非旧 ckpt；④ 用 per-decision 诊断量 + 冻结闸门 A 早期筛选；⑤ 新池 `7_200_000+300` 探索性评估 |
| 成本 | 微调 ≈**2–5 h**（估算，复用已有 1.6M 行教师 Q，**零新增 109.5 ms/状态标注**）；评估 ≈**2–3 h**（贪心口径）⇒ 合计 **≈4–8 h** |
| 预期收益 | 开源实测：TanyaoDojo Q anchor 得 `−0.75±1.31 @12k`、配对 **`+1.75 (z=2.58)`** 优于此前最佳；但**锚错 ckpt 两小时内退回旧打法**（riichi 率 41.1%→44.4%，`−1.26, z=−1.81`），锚对则 `+1.48±1.42 (z=2.05)` ⇒ 预期 `+0~+0.5 分`，方差大、置信度中低 |
| 判据（看前锁死） | 主口径 `mean ≥ +1.478 + 0.3 且 p<.05` 才算有增量，同时 per-decision 诊断量不得出现回退；ns 只写「无足够证据」 |
| 风险 | 「critic / Q 拟合更好 ≠ 外部更强」（TanyaoDojo oracle-critic 掉 3.2 pt）；本项目教师 Q 的非最优动作未校准（Mortal FAQ），锚定目标需按 Q 熵加权 |
| 优先级 | **P1/P2 待裁定**；若判定为改主链则降为 P2 并需单独批准 |
