成本上 v3 网络前向占 94~98%，是唯一值得压缩的杠杆。

## 4. 复现方式

```bash
# 1) 恢复 9 片主数据（归档内已带 runs/gates/ 路径；本地原文件仍在，此步用于干净克隆）
tar -xzf reports/评估主数据-9片.tar.gz -C .

# 2) 复算 E-STAT / E-ALIGN 的全部报告（零算力，<1 min）
.venv/bin/python tools/estat_align_audit.py

# 3) 重建 Rust 内核 / 教师标注二进制（本次删了 target/，需要训练时才做）
bash rust_engine/build.sh

# 4) 重新导出 ONNX 缓存
.venv/bin/python tools/export_onnx_cache.py

# 5) 线上服务与来源核验
.venv/bin/python tools/web_hint_verify.py
```

**后端口径（避免重犯「以为训练也被 28 s 拖慢」的误判）**：训练用 PyTorch-MPS 梯度反传（ORT 不能训练）；
教师标注走 ORT-CoreML 但权重恒为 v1 `dushan_master.onnx`（实测 11388~11401 标注/h/worker，100k 约 2.2 h）；
全部离线评测 `--device mps`；线上 `search_device_for()` 让 v1 走 ORT、v3 走 MPS。
**27~28 s 只出现在「线上 ORT-CoreML + v3 真档」组合**，历史训练与评测从未使用，未浪费机时。
