# E-SLIM 学生能否继续提升：编码器、瓶颈与未实验方法的重排（2026-11-11）

> **文件性质：分析 + 计划，不是批准。** 本文不启动任何训练、评测、定时任务，
> 不改 `champions.json` / 预登记判据 / 线上模型。任何实验须用户点名批准并另立预登记。
> 依据：本仓库实测（`docs/14天训练计划.md §6.43 / §6.72 / §6.73`、

## 0. 三句话结论

1. **编码器**：学生用的是 **v3（`encoder_version=3`，63 通道 / 130 全局维，a–g 七个包全开）**，
   与教师 `champ_exit_p48` **逐位一致**；`master` 是 v1（15/70）。编码器本身不是本轮可调杠杆，
   但 v3 预留的 **packs 消融**是一个从未用过的单变量诊断工具。
2. **能继续提升，但不是靠"再训几轮"**（"性能"分两义：**棋力**见下；**速度/包体**见 §4.1 的
   A6/A7）：TA/S1 的 val 曲线都已走平，容量 gap 也基本没吃到；
   瓶颈在**教师信号与数据**（学生拟合的是 16 轮历史 DAgger 的搜索 Q，不是最终 P48），
   以及**搜索档棋力完全没测**（搜索值 ≈3 分，学生 N32 仅 0.275 s）。
3. **继续 PPO / DAgger 基本不能提升，且当前被门禁冻结**：48 轮实证已饱和（M=−0.090±0.222）、
   PPO 加速段 11 轮全 ns、最后一轮 DAgger 还出现**负迁移**；E-ALIGN 一致率 61.70% < 95%
   ⇒ 冻结一切新 RL / 奖励塑形 / Q 锚定。**唯一没被冻结的 DAgger 变体是 E-TEACHER**
   （改教师口径的纯蒸馏），而它恰恰是最值得做的那一条。

## 1. 编码器：精确事实

`models/slim_s.pt` / `models/champ_slim_s.pt`（两者 md5 相同 `333516a5…`）实际元信息：

```
encoder_version = 3
encoder_packs   = ['a','b','c','d','e','f','g']        # 全开
net.in_channels = 63      net.global_dim = 130
```

| 模型 | 编码器 | 输入 | 说明 |
|---|---|---|---|
| `slim_s` / `champ_slim_s`（0.814M） | **v3 全 packs** | 63 ch × 27 + glob 130 | 本轮学生 |
| `slim_ta`（1.990M，教师助教） | v3 全 packs | 同上 | 两级蒸馏第 1 级 |
| `champ_exit_p48`（9.837M，教师） | **v3 全 packs** | 同上 | 与学生逐位同口径 |
| `dushan_master`（0.769M，线上主力） | **v1**（ckpt 无 `encoder_version` 字段，旧格式默认 1） | 15 ch / glob 70 | 不可拿 v3 张量测速 |

`zhuoji/encoder_v3.py` 的要点：

- v3 是 v2 的**严格超集**（`tiles[:31] == v2.tiles`、`glob[:98] == v2.glob`，有测试断言）。
- `a/b/c` 沿用 v2；新增 `d` 长时序牌河（ch 31–42）、`e` **横鸡轮与鸡牌状态**（ch 43–52）、
  `f` 放铳风险与手牌结构（ch 53–62）、`g` 全局扩展（glob 98–129）。
- 红线：**只用公开信息**，绝不读对手手牌；对手状态一律是公开信息推断的启发式。
- §6.73.1 预登记写死"编码器版本恒 v3，**不做降级**"——省下编码成本会丢信息，判据不许动。
- **但 packs 可单独关**：关掉 d/e/f/g 时输入与 v2 完全一致，架构与参数量不变 ⇒
  这是为「纯容量 vs 容量+新特征」单变量消融预留的能力，**E-SLIM 全程没用过**，
  可用来定位「学生差的 1.05 分是容量不足还是特征没用上」。

## 2. 瓶颈归因：为什么"继续训"没空间，空间在哪

| # | 实测事实 | 推出的判断 |
|---|---|---|
| 1 | TA ep11 早停 `val 1.7900`；S1 16 轮满跑 `val 1.7929`，曲线走平 | 同一数据 / 损失 / 容量下**优化已收敛**，堆 epoch 无空间 |
| 2 | S1 0.814M vs TA 1.990M，val 只差 **0.0029** | KataGo 担心的 **capacity gap 基本没吃到**；加大容量收益有限 |
| 3 | 蒸馏数据 = `runs/exit_r01..r48` 的 16 轮 × 4 分片 = **1.6M 行历史教师 Q**，由各轮当时的主链检查点做 `n32-ply3` 搜索标注 | 学生拟合的是**历史平均教师**，而最终教师 P48 是第 48 轮 PPO 加速轮 ⇒ 存在**教师漂移**，这是 −1.053 的可疑来源之一 |
| 4 | 同池配对差：学生 − P48（同一批 master+N32 对手）= **−1.053 ± 0.520**，p≈0.044 | 可提升空间的上界量级就是「1 分左右」，不是「差一大截」 |
| 5 | 搜索价值 **+2.997 ± 0.551**（`P48g·masterg − P48g·master+N32`）；学生 N32 仅 **0.2749 s**（P48 的 1/6.6） | **最大未兑现的一格**：学生带搜索的棋力**从未测过**，零训练成本就可能"变强" |
| 6 | 学生贪心 vs master+N32 = **+0.855 ± 0.266**（600 seed） | 学生只用贪心就已胜过**开了搜索**的线上主力 |

**结论**：能提升，但杠杆优先级是
`(A) 把搜索用起来 > (B) 换更强/更新的教师信号与 on-policy 数据 > (C) 工程侧降延迟`，
而 `(D) 同配方继续训练 / 继续 PPO` 排在最后且被实证否定。

## 3. 继续 PPO 和 DAgger 能否提升？分层回答

### 3.1 主链（P48 谱系）继续 PPO / DAgger —— 实证否定

| 证据 | 数值 |
|---|---|
| §6.43 统计早停主判据 M | `−0.090 ± 0.222`，`p=.685`（P44 vs P36，独立池 600 seed）⇒ 无提升 |
| 闸门 A 斜率 | `+0.0151 ± 0.0203`，`p=.456`（无斜率）；entropy `0.858→0.649` 已平 |
| S3 PPO 加速段 P37–P47 | 闸门 D **11 轮全 ns**，无一次晋升；均值 +4.60，无一轮 <4.2 |
| S3 收官 DAgger R48 | 闸门 A `+4.121±0.401`（S3 最低）；同池直接对局 **−0.944±0.383, p=.0136**，全程首次 **DAgger 负迁移** |
| 早停后的经济判断 | 同配方重启期望增益 ≈0，成本 ≈**100 h** 机时 |

补充一个容易忽略的事实：**P48 本身就是 PPO 产物**——其检查点带
`ppo={init: exit_p47, hands: 960, states: 41011, epochs: 2, lr: 5e-5, shaped: true,
phi_scale: 8}` 元信息。也就是说"继续 PPO"不是没试过的新方向，而是**已经作为主链加速段
跑了 11+ 轮、并交付了最终冠军**的既有手段；再续跑的边际收益已被 §6.43 早停量化为 ≈0。

文献旁证（§2.3 / §2.6）：TanyaoDojo 四次连续 RL 负结果，critic 拟合误差改善 100× 反而
掉 3.2 分；修正为整场名次对齐奖励后退化消失，但 **1B steps 仍只换来与基线统计持平**；
MDPI 记录 60 轮 PPO / 6 万局自对局后 RL 未超老师（`−0.021±0.042`，全在 CI 内）。
⇒ **不要期待靠 RL 微调获得大幅提升**，这是本项目与公开证据共同指向的结论。

### 3.2 门禁：现在"继续 PPO"不是技术问题，是未获批准

`E-ALIGN`（§6.72.4）主数据集逐行符号一致率 **61.70% (1234/2000) < 95%** ⇒ 机械判读
「目标未对齐」，按 §3.4 自动生效：

> **冻结 E-REWARD（名次辅助头）、E-ANCHOR（Q 值锚定微调）与任何新 RL / 奖励塑形 /
> Q 锚定立项**，直到用户批准目标定义修订。

三个待批准选项（`reports/E-ALIGN-目标对齐审计.md §7.2`）：
① 保持分差目标（0 成本，只改对外表述）；② 评测侧加名次口径（极低，不改训练）；
③ 训练侧改名次加权（**改主链配方，需重标 + 全曲线重跑，与历史曲线不可比**）。
**只有批准其中一条，新 PPO 才可能解冻**；且 ③ 恰是 TanyaoDojo 四次负结果警示的方向。

### 3.3 给「学生」做 PPO —— 先验更低

- 学生是**纯蒸馏产物**（`distill.kind = exit-slim`），RL 微调会破坏对教师 Q 的保真；
  要保真就得加 Q-anchor（E-ANCHOR），而它**正好被冻结**。
- 「拟合更好 ≠ 外部更强」：学生 val 已 1.7929，TanyaoDojo 的 `v_loss 0.102→0.001
  却掉 3.2 分` 是直接警示。
- 若真要做，必须先解冻门禁 + 写死「训练奖励与评测统计量的对齐证明」+ 单独预登记。

### 3.4 但 DAgger 的**核心思想**恰恰是最有希望的一条

不要「继续第 49 轮主链 DAgger」，而要把它换到学生身上：

> **让 `slim_s` 自己 rollout 出它真正的弱区状态，用当前最强教师 `champ_exit_p48`
> 做 `n32-ply3` 搜索重新标注全 28 槽 Q，再蒸馏回学生。**

- 这正是 `gen_exit.py` 的 `--student / --teacher` 语义（学生 rollout + 专家标注），
  也就是 DAgger 的 on-policy 数据聚合；**它是纯蒸馏，不改训练目标 ⇒ 不受 E-ALIGN 冻结**。
- 归类上属于 `E-TEACHER`（改教师口径的 DAgger），§6.72.4 明确「不受本门禁冻结」，
  但**仍未批准**。
- 与 B3 的区别：不重跑主链 48 轮，只对学生的弱区做**一次**数据刷新，成本量级小得多。

| 方法（来源） | 冻结原因 | 解冻后的价值 |
|---|---|---|

### 4.3 单机不可行 / 已判无效（登记不排）

- **AlphaStar League / PSRO**（14 天 × 256 TPU v3 + 4100 CPU）、**AlphaStar Unplugged**（280 万局）、
  **Suphx Oracle Guiding / pMCPA**（每回合 ≈100K rollout，线上实战并未启用）、
  **ReBeL PBS+CFR**（不完全信息下 AlphaZero 式叶节点替换不 sound）⇒ 算力远超单机。
- **Mortal CQL / IQL**：本项目教师 Q 来自**搜索实测标注**而非 bootstrap 外推，
  天然规避 OOD 过估计 ⇒ 不需要引入，这是文献调研已经替我们排除的一项。
- **KataGo playout cap randomization**：主链内采样杠杆；蒸馏不跑搜索 ⇒ 不适用。
- **INT8/INT4 量化**：Apple Silicon AMX 无 int8 matmul、M3 Ultra CoreML 全量化级别零加速 ⇒ 明确无效。
- **Rust 重写推理**：前向占 94–98%，理论上限 2–6%；教师标注侧**已**是 ORT + Rust 内结算（109.5 ms/状态），Rust 已用尽。

## 5. 最小可执行包（**待批准**，本轮不启动）

按长任务纪律先剖析成本：教师标注的 109.5 ms/状态来自 ORT 前向 + `Search::settle_internal`，
**Rust 侧已优化到位，无进一步空间**；评测的瓶颈是 N32 每局 ≈20 s（按「局」估，不能按单步推）。

| 阶段 | 内容 | 成本（实测外推，开工前 1 seed 冒烟校准） |
|---|---|---|
| **P0（零训练）** | 学生 `search32` vs `master+N32`，新池 **`7_500_000..7_500_299`**（评估专用，登记后永不复用）；同池补一条学生贪心作锚 | ≈1–2 h，5 worker |
| **P1** | A2：`gen_exit.py --student models/slim_s.pt --teacher models/champ_exit_p48.pt --enc-version 3 --device ort`，只对 contested 子集（建议高熵 30%，≈480k 行）重标；与旧数据混合重蒸 S1 | 重标 ≈2–4 h 墙钟 + 重训 ≈1 h + 闸门 ≈1 h ⇒ **≈4–6 h** |
| **P2** | A3/A4/A5 作为 P1 的**训练集内消融**，不进判定池；A6 单独做工程验收 | 近零 / 1–2 h |

**P1 的预登记要点（沿用 §5 模板，看结果前锁死）**：

- 唯一问题：用最终教师重标 on-policy 数据，能否把学生与 P48 的配对差从 `−1.053` 收窄。
- 不改：训练目标（仍是教师 Q 的 softmax + maxQ/8）、评估统计量、1v3 四座旋转、编码器 v3、δ。
- 主判据：**同池配对差**。在池 `7_600_000..7_600_299` 上**同时**跑两条臂
  「旧 `slim_s` 贪心 vs master+N32」与「新学生贪心 vs master+N32」，逐 seed 相减，
  要求 `Δ(新−旧) > 0` 且 `95% CI 下界 > 0`；工程 5 项不得回退。
  ⚠ P0 的 `7_500_000` 片只回答「搜索档值不值」，**不得与 P1 数字相减**（跨池 + 跨对手）。
- 终止：重标后闸门出现负向即停，不追加算力；τ / β / 混合比例不得事后调。
- 回滚：只增不替，`champions.json` 不动，线上主力恒 `dushan_master`。

## 6. 边界

- 本文是**分析**，`docs/后续实验计划-2026-11-10.md` 开头的「文件性质：计划，不是批准」
  与「未点名前不启动训练、不启动评估、不改线上模型、不重跑已耗池」继续生效。
- 已耗池：`610000 / 900000 / 710000+300 / 720000+50 / 3M+500 / 4M+1000 / 5.1M+500 /
  6M+120 / 7_000_000 / 7_100_000 / 7_200_000 / 7_300_000+300 / 7_400_000+600`。
- 1v3 结构下**差值不可加**（`reports/E-SLIM-学生瘦身.md §6.5` 实测 6.6 倍）：
  跨臂数字不可相减外推，任何强度结论必须写明对手构成。
- 不把 `p>.05` 写成「持平 / 到顶」；`ns` 只写「无足够证据」。
