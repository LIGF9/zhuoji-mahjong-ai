## 0. 一页结论

**瓶颈不是"算力不够"，也不是"容量不够"，而是三件事叠加：**

1. **训练信号衰减到接近 0**：策略越练越尖，采样到的动作 logπ ≈ 0、优势近乎噪声 →  
   REINFORCE 梯度自我熄火（实测 `pi` 损失 ≈ −0.03，对比典型 `|logπ|≈1.2`）。
2. **两个"自适应"控制器 2450 轮里全程失效**（**硬证据**，见 §1.D1）：`ent_coef` 与  
   `kl_coef` 从第 2 轮起就一直钉在各自下限，所谓"自适应熵/KL 锚"其实从没工作过。
3. **能力无法凭空长出来**：M1 是随机初始化骨干 + 只有 26.5 M 样本（**2.7 样本/参数**），  
   而它要追的对手 `dushan_master`（0.77 M 参数）是同一套管线里滚了 12 代的老手。

**结论 → 方案主线（三段式，约 22–27 小时）：**

| 段        | 名称        | 核心动作                                                         | 时长              | 目标                                       |
| -------- | --------- | ------------------------------------------------------------ | --------------- | ---------------------------------------- |
| **M2-0** | 瓶颈诊断      | 动作一致率分解 + 强度分解 + 耗时剖析                                        | ~1.5 h          | 定位"差距落在哪些决策"，定 β 与辅助头优先级                 |
| **M2-A** | 修复 + 能力移植 | 熵目标重写 / 探索下限 / 滚动锚 / **KLT 教师蒸馏（β 退火）** / 对手池重构 / GAE / 吞吐修复 | 8–9 h（600 轮）    | vs master 由 −3.11 改善 **≥ +1.5**          |
| **M2-B** | 超越        | 撤教师、名人堂对手池、长跑                                                | 12–16 h（1200 轮） | vs master **≥ +0.5**（追平）/ **≥ +1.5**（超越） |

**最关键的单个杠杆**：把"KL 锚"从**锚自己（冻结旧版）** 改成  
**锚最强（master 的策略分布）+ 权重退火**（DeepMind *Kickstarting DRL* 的成熟做法，  
DMLab-30 上用 **1/10 环境步数**达到 from-scratch 水平并**反超教师 40%**）。  
这不是"BC 预热"（历史实测是负资产），区别见 §3.R2。

### 1.1 七条证据

**D1 ·【硬证据】两个自适应控制器全程钉在下限，等于没开**

`selfplay.py::adapt_coefs()` 的规则是：  
`ent < ent_floor(0.45)` 才加大熵奖励；`ent > ent_floor×2.2 = 0.99` 则把 `ent_coef` **除以 1.5**。

而实测熵 H 全程在 **1.16 – 2.08**，永远 > 0.99 → 控制器**每次都往下压**，  
`ent_coef` 从初值 0.01 在第 1–2 轮就被压到下限 **0.03** 并保持到段末：

```
iter   1  H=1.540  ec=0.030 kc=0.020
iter 401  H=1.183  ec=0.030 kc=0.020
iter 801  H=1.164  ec=0.030 kc=0.020     ← 850 轮里 ec 一个数没变过
```

KL 同理：`kl_target = 0.25`，而实测 KL 从 0.005 单调涨到 0.177，**从未越过 0.25**  
→ `kl_coef` 也一直停在下限 **0.02**（S1 段仅因某轮越过 0.25 抬到 0.051）。

> **含义**：S1/S2/S3 实际上都是**固定超参**在跑（ent_coef=0.03、kl_coef=0.02）。  
> 库里那套"自适应熵 / 自适应 KL 锚 / 熵 watchdog（<0.12 触发）"**从未触发过一次**。  
> 熵从 1.54 掉到 1.16 的整个过程，**没有任何机制出手**。

**D2 · 熵单调下滑且无对抗力**

| 段  | 段首 H  | 段末 H  | 跌幅     |
| -- | ----- | ----- | ------ |
| S1 | 2.076 | 1.742 | −0.334 |
| S3 | 1.540 | 1.16  | −0.38  |

Suphx 论文原话：*"RL 训练对策略熵非常敏感：熵太小时 RL 快速收敛，**自博弈不再显著改进策略**"*——  
这正好对应 S3 后半程 510 轮净增 +0.227（落在 CI 内 = 零）。

**D3 · 策略梯度信号趋于消失**

`pi`（REINFORCE 损失）= `−E[logπ(a)·A]` ≈ **−0.02 ~ −0.08**。典型 `|logπ| ≈ H ≈ 1.2`，  
若优势与动作方向完全相关应达到 ~1.2 量级 → 实测只有 **~2.5%** 的解释力。  
同时价值头在退化（S3 段 `V` 损失 0.57 → 0.87，比"预测常数均值"还差）→ 优势项更接近纯噪声。  
**这就是"平台期"的机制：不是梯度算错了，是没有梯度可算了。**

**D4 · 数据/参数比低 1–2 个数量级**

9.84 M 参数只见过 **26.5 M 样本 = 2.7 样本/参数**。同量级麻将网络（Mortal 10.8 M）用的是  
10⁸–10⁹ 量级样本。**10M 模型的"容量红利"根本没被兑现，它一直是欠训练的。**

**D5 · 34% 的 wall clock 花在固定开销上**

65.6 s/轮 = 采集 10 s + 更新 33 s + **22.6 s 开销**。开销里最大一块是  
**679 次进程池重建 / 850 轮 = 每 1.25 轮一次**，而触发条件是"**系统**内存 ≥ 75%"  
（23.85 GB）—— 日志显示那时**训练进程树只有 10.5 GB**，即触发源是桌面自己的  
11–14 GB 常驻占用。**重建既没用（内存不在训练里），又很贵（12 个 worker 重启 + 重载 8 份快照）。**

**D6 · 与目标对手 master 的交手率只有 ~5%**

`--snapshot-pool dushan_master` 把 master 塞进 9 元均匀池，池分支只以 30% 触发、占 1–2 个座位  
→ master 约 **0.3×1.5/9 ≈ 5% 的座位**。**要打赢谁，就得跟谁多打。**

**D7 · 训练内 40 副评测（±1.6）没有判读力，选点实际失效**

`--eval-every 20 --eval-rounds 40` 的 `vs_anchor` 噪声 ±1.6，而 M1-S3 的 `guard` 最终  
每次都取末轮 → 段内"选点"名存实亡（这也是 S3 选点复核结论的反面确认：40 副能把最差点排成最好点）。

### 1.2 鸡牌信息审计（2026-10-14 追加，回答「模型到底有没有考虑鸡牌」）

用 300 副教师对局 + 930 个冻结决策点实测。**结论：鸡牌是模型的主战场，已编码部分可用、  
确实在用；但有三处系统性缺口，其中一处覆盖 22% 的鸡分。**

**A. 鸡分是整个游戏的主导得分通道（61.6%）**

| 构成                             | 占比        |
| ------------------------------ | --------- |
| 鸡（冲锋鸡/横鸡/幺鸡/手中鸡/捉炮鸡/翻鸡/责任鸡/包鸡） | **61.6%** |
| 牌型与终局赔付                        | 22.8%     |
| 杠分                             | 8.1%      |
| 点炮等其余                          | 7.5%      |

而 RL 奖励 = `score_delta`（进 `pair` 矩阵的鸡数差 + 牌型 + 包鸡包杠），**鸡分是完全进损失的**。

**B. 已编码的鸡信息（v3 共 9 处，全部实测点亮）**

| 特征                       | 含义                                                   | 打牌决策点点亮率  |
| ------------------------ | ---------------------------------------------------- | --------- |
| `tiles[50]`              | 本局鸡牌种（幺鸡 + 开局翻鸡种）                                    | 常显        |
| `tiles[51]`              | 自己手里各鸡牌张数 / 4                                        | —         |
| `tiles[48]`              | **现在打这张会是「横鸡」**（引擎同源 `ji_name_if_discarded`，含同轮跟打口径） | **37.9%** |
| `tiles[49]`              | **现在打这张会是「冲锋鸡」**                                     | **8.1%**  |
| `tiles[47]`              | 是否还有横鸡轮开放（跟打仍算横鸡）                                    | 6.9%      |
| `tiles[43–46]` / `[52]`  | 四家开轮次数 / 已被别家碰杠走的鸡牌张数                                | —         |
| `glob[74–77]`            | 四家已亮明鸡数                                              | **88.2%** |
| `glob[96]`               | 包鸡风险敞口                                               | **82.7%** |
| `glob[97]`               | 自己手牌鸡价值                                              | 17.3%     |
| `glob[98–108]` / `[128]` | 因鸡被碰杠次数 / 打出鸡次数 / 横鸡轮总体状态 / 鸡事件总数                    | —         |

（`hengji_active` / `hengji_species` 是 `@property`，曾被误判为死特征，实为可用——记录以免复发。）

**C. 消融证明模型确实在用（930 个冻结局面的严格配对查询）**

| 臂                    | 与全特征一致率              |
| -------------------- | -------------------- |
| 关掉鸡包 e（ch 43–52）     | **91.3%**（8.7% 决策改变） |
| 关掉长时序牌河包 d（ch 31–42） | 93.1%（6.9% 改变）       |

即**鸡包的边际影响与长时序牌河包同量级**，不是摆设。行为侧：在手牌含「打出去就是冲锋鸡/横鸡」的  
幺鸡、且存在安全替代牌的 **123 个局面里，模型选择风险牌 0 次**（随机基线约 7–8%）。

**D. 三处缺口（按金额排序）**

| #      | 缺口             | 体量                       | 为什么重要                                                                                                                                                                                     |
| ------ | -------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **J1** | **结算翻鸡完全未编码**  | **占鸡分 22.2%，97% 的局都会产生** | 胡牌者翻牌墙顶定「翻鸡牌」，听牌者手中每张 +1；若翻出的种与本局开局定下的鸡牌重合 → **金鸡 ×2**（`jin_ji_multiplier=2.0`）。它在决策时是随机变量，**但它对状态的期望值是确定的公开信息**（= Σ 手上牌 × P(该牌成为翻鸡)）。现在模型完全看不到 → **持鸡的期权价值被系统性低估**，且无法区分"我这手牌恰好压在翻鸡高概率区" |
| **J2** | 包鸡敞口只有 **0/1** | 包鸡是鸡分里**单项最大（29–40%）**   | `glob[96] = 未听牌 × 他家已亮明鸡>0`，不含「我自己已亮明多少鸡（= 我要赔多少）」、不含「离听牌还有多远（冲听 vs 弃听的赌局核心）」。另有 **41% 的局以荒牌流局收场，而流局鸡与杠一律不结算** → 整条风险-收益曲线依赖「打到终局的概率」，现在只有 `glob[95]/[127]` 的粗略墙剩量代理                      |
| **J3** | 责任鸡溢价没有前瞻风险项   | 占比小（2.7%）                | `tiles[48/49]` 只说"这张会记成什么鸡"，不说"被碰走后我要赔多少溢价"。可并入 J1 的同一个包                                                                                                                                  |

**E. 还有一个更隐蔽的问题：编码器对规则开关完全无感**

`encoder.py:122` 取 `cfg = game.cfg` 但**从未使用**；三个编码器里没有任何一处读  
`jiesuan_fanji / end_baoji / mantiangji / jin_ji_multiplier`。训练期配置固定，影响可控；  
但网页设置里这些开关可自由组合，**模型无法条件化**——一旦用户改规则，模型的鸡分直觉就会失准。

**F. 对 M2 的落点（不改变主线，只加一个小包）**

- **新增 encoder v4 包 `h`「鸡牌期权」**（约 8–10 维，成本可忽略）：  
  ① 翻鸡期望价值 `Σ_t hand[t]·P(flip = t−1)`（用 `4 − 可见张数` 算，纯公开信息）；  
  ② 金鸡期望：各鸡牌种成为翻鸡牌的概率（幺鸡/开局翻鸡种各一维）；  
  ③ 包鸡应付金额估计（自己已亮明鸡数 × `ji_hold`）× 未听牌指示；  
  ④ 距听牌的墙剩量（`wall_left` × 未听牌）——已有的 `glob[127]` 保留，另给"若不进张还需几巡"的粗估。
- **红线不变**：与 v3 的 a–g 包一样，只许用公开信息，不得引入任何未来量；超集性质用测试断言锁住。
- **期望管理**：J1–J3 是**特征缺口，不是瓶颈主因**。§1.1 的 D1/D3 才是平台期的直接机制  
  （梯度自我熄火）。所以 v4 包**挂在 M2-A 一起上**（与 KLT 蒸馏、AER 熵控制同批），  
  并且**必须走 A/B 单变量消融**（开 h vs 关 h，架构与参数量不变）来判定它到底值多少分，  
  不允许"加了就默认有效"。

### 一句话综合

> **架构不用换**（10M + SE 是麻将甜点区，Mortal 已验证）；  
> **算法不用换**（PG 系仍为主力）；  
> 要换的是 **① 让探索活着 ② 让梯度有信号 ③ 把"已在手的强策略"当作可蒸馏的资产而不是只用来自评**。

### M2-A · 修复 + 能力移植（600 轮 / 8–9 h）

**A1 · 熵控制器重写（AER 式，替换 §1.D1 的死规则）**

```
H₀ = 段首 25 轮熵均值（M1-S3 段首 ≈ 1.54）
H* = 0.75 · H₀                         # ≈ 1.15，落在"不坍缩但仍有探索"的带内
死区 ±0.03；比例控制：
    ent_coef ← clip(ent_coef · exp(η·(H* − H)), 0.01, 0.5)      η = 4
```

**A2 · 探索下限（保证 ∇ 不为零）**：自博弈采样时以 **ε 概率替换为均匀合法动作**，  
ε 从 **3% 线性退火到 1%**。理由：让被采样动作的 `logπ` 远离极值，  
梯度不再随"策略变尖"而自我熄火（这是 D3 的直接对症药）。

**A3 · 滚动 KL 锚 + 可达目标**：`kl_target 0.25 → 0.05`；`kl_coef` clamp **[0.01, 0.5]**；  
每 150 轮把锚刷新为**当前策略的 EMA（0.7/0.3）**——避免长段内锚点过期（R8）。

**A4 · KLT 教师蒸馏（主引擎）**

```
loss = loss_RL                    # −logπ·A + 0.5·V + GAE 优势
     − ent_coef · H(π_θ)
     + kl_coef · KL(π_θ ‖ π_EMA)               # 滚动锚
     + β(t) · KL(π_master ‖ π_θ)               # ← 新增：reverse-KL 到 master
β(t): 0.4 → 0，线性退火，300 轮归零（之后留 0）
```

- `π_master` 在同一批自博弈状态上前向一次（0.77 M 网络，**只前向不反向**，开销 ≈ M1 前向的 8% → 单轮 +3%）。**零额外采集成本**。
- **必须用 reverse-KL**（`KL(π_master ‖ π_θ)`）：这是**质量覆盖**方向，M1 只需在 master 认为可能的动作上接近，  
  仍保留自己的多峰探索；用 forward-KL 会把自己的分布压进 master 的模式 → 提前锁死。
- **退火到 0 是硬要求**（Kickstarting 的"self-regulation"性质）：否则上限被钉在 master。

**A5 · 对手池重构**：master **移出快照池**、提为**一等对手**（独立分支、  
每局出场概率 0.30，命中后只替换 1~2 个座位 → 稳定占 **11.3% 座位**，与池里有几份  
自快照完全无关；旧写法满池时只有 1.4%）；自快照按**新近度加权**；  
`teacher_prob 0.05 → 0.00`（弱规则 bot 只贡献"简单局"，信息量低）。

> 注意：**对手总占位必须留在 0.5–0.9 座位/局**。若写成"每座位独立掷骰"，  
> 占位会飙到 2.4 座位/局、samples/轮腰斩 45%（2026-10-14 冒烟实测，见 §5.1③）。

**A6 · 优势估计升级**：`GAE(λ=0.95, γ=1)` 替换纯 MC 优势（手内自举，手末取终局分）；  
优势**按座位 (role) 标准化**（RAE，SPIRAL 的做法）而不是整批混合标准化。

**A7 · 吞吐修复（目标 65.6 → ~48 s/轮，+35% 轮次）**

- 优势估计改用**采集时回传的 value**（去掉主进程那次全量前向，省 ~10 s/轮，逐位等价）
- KL 锚前向**按轮次降频**：`--kl-anchor-every 4`（省 ~7 s/轮；不是"换 master 规模"，  
  因为 master 是 v1 编码器、吃不了 v3 的输入张量）
- pool 重建判据：系统百分比 → **训练进程树 RSS ≥ 16 GB**；`--pool-rebuild-every 150 → 250`
- 每 worker 快照数 **8 → 4**（重建代价近似减半）
- `--eval-every 20 → 40`，`--eval-rounds 40 → 120`（总开销不变，但信号从 ±1.6 收到 ±0.9，**仅作监控**）

**A8 · 优化器**：`lr 6e-6 → 1.2e-5`（信号修复后不该再压步长），余弦退火到 4e-6。

**A9 · 辅助头（按 M2-0 结论决定是否上）**：对手手牌预测头（3 家 × 27 多标签 BCE，权重 0.1，  
输出层**零初始化** + 20 轮 ramp）。文献依据：不完全信息博弈里信念/对手建模辅助任务是表征学习的  
有效信号；而本项目自己的结论正是"**表征是瓶颈**"。

> **门禁 G1（第 300 轮，约 10 min）**：1200 副配对 `M1-A300` vs `master` vs `M1-S3`。  
> 判据：`vs master ≥ −1.6`（即相对 S3 至少改善 **+1.5**，为 S3 段全程增益的 1.5 倍）。  
> **不达标 → 关 β 重跑 A 段**（证明"蒸馏"无效而非"其他修复"无效，避免把功劳记错）。

### 5.1 三处必须写下来的实现细节

**① A4 的教师前向必须挪到 worker，而且教师必须"自己重新编码"**  
`dushan_master` 是 **v1 编码器 / 64ch**，M1 是 **v3 / 63 通道** —— 两者的输入张量  
**不能共用**。所以 `KL(π_master ‖ π_θ)` 的教师一侧要在 worker 里  
用 v1 对**同一局面**重编一次再前向。好处是这份开销从**串行主进程**移到了  
**12 个并行 worker**（顺带省掉主进程那 0.97 s）。β 退火到 0 之后连这次前向下发都停掉。

**② A7② 的"KL 锚降频"用轮次降频实现，不是缩网络**  
原计划写"降频或换 master 规模"。换 master 规模在这条链路上不成立（同上，master 是 v1）。  
所以实现为 `--kl-anchor-every 4`：锚只前向不反向，占单轮 ~9 s，4 轮做一次 →  
省 ~7 s/轮。**副作用必须处理**：跳过的那几轮 `update()` 返回的 `kl` 是 `None`，  
自适应控制器**不能**把它当成"KL=0"（否则会把 `kl_coef` 一路衰减到下限）——  
所以 `None` 时跳过 KL 分支，history 里另写"最近一次有效 KL"。

**③ A5 的"一等对手"是分支级权重，不是座位级**  
见上表 `vcollect.py` 第 4 条。一句话：**对手总占位必须留在 ~0.5–0.9 座位/局**，  
只把"谁来坐"从"1/9 均分"换成"master 固定 11.3% 座位（与池子大小无关）"。  
实测分布（4 万局解析解）：

| 口径                                   | master    | 自快照   | bot  | 主模型   |
| ------------------------------------ | --------- | ----- | ---- | ----- |
| M1-S3 旧口径（mp=0，教师 0.05，池=master 1 份） | 11.3%     | —     | 1.9% | 86.8% |
| M1-S3 旧口径**满池**（池=master+8 自快照）      | **1.4%**  | 9.9%  | 1.9% | 86.8% |
| M2-A 新口径（mp=0.30，教师 0）               | **11.3%** | 11.2% | 0%   | 77.5% |

### 5.2 验证阶段抓到的三个「静默」控制器缺陷（2026-10-14）

第 3 步落地后做「全特性冒烟 + 单测」时抓到三个缺陷。它们的共同点是**不会 NaN、  
不会报错、只会安静地把系数钉在某个端点上**，然后在几百轮之后以"熵塌了""学不动"  
的形式暴露 —— 而那时已经无法区分到底是算法错还是控制器错。所以单独记在这里。

| #      | 缺陷                                                                                                                            | 证据                                                                                             | 修法                                                                                                                                 |
| ------ | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **C1** | 熵基线窗口（段首 25 轮）里 `step()` **提前 `return`**，把 KL 分支一起吞了 → `--anchor-warmup 0` 的段前 25 轮 KL 无人干预                                   | 冒烟 iter 5 的裸 kl=0.1540（目标 0.05 的 3 倍）而 `kc` 全程钉 0.020                                          | 拆开两侧：基线窗口只冻结 `ent_coef`，KL 侧照常（单测 T1a/T1b）                                                                                         |
| **C2** | **η（熵比例增益）= 4.0 过大**：`ec` 在 `[0.01, 0.5]` 两端继电器式来回                                                                            | 玩具被控对象 η 扫描：η=4 时 **67.4%** 的轮次贴着 clamp 端点、H 稳态偏离目标 **−0.384**；η=0.5 时钉端 0.0%、偏离 −0.014        | 默认改 **0.5**（"持续偏 0.10 nat 时 20 轮推一个 e 折"），类属性 `ETA_DEFAULT` 作单一事实源（单测 T8 扫描留档）                                                     |
| **C3** | **`--kl-target` 的判据量纲错了**：裸 `kl` 是「距锚点的**距离**」，锚点 150 轮才刷新 → 健康训练也会涨到 1+；0.05 用距离口径 → **每次测量都触发**、25 轮内把 `kc` 顶到 clamp 上限 0.5 | 冒烟 4 个测量点：距离 0.0232→0.1540→0.2564→0.3284（看着在爆），**换算成每轮率却是 0.0232/0.0308/0.0285/0.0253——稳得像常数** | 判据改为 **率 = `kl` ÷ 锚点年龄**（锚点年龄由主循环做单一事实源，建锚/EMA 刷新/看门狗回退三处归零）。对 `--kl-anchor-every` 与 `--kl-anchor-rolling` 都**不变**（单测 T4c/T4d/T4e） |

**C3 的连带修正**（同一个量纲错误出现在第二、第三处）：

- **放松阈值** `0.4×target`（=0.02）会与实测正常率（0.019–0.031）**重合** →  
  每个测量点都在"放松"、`kc` 被静默衰减到下限 0.01，改掉历史基线。  
  新增 `--kl-relax-ratio`，默认 **0.25**（带下沿 0.0125，约为正常率的一半）。  
  不对称是有意的、风险导向的：过度锚定会把学习锁死（致命），锚项偏弱只是少一层  
  温和正则（可接受）→ **快刹车、慢松手**。
- **看门狗**的 `kl > 2.5` 同样成立于"每轮一测"的时代（那时 `kl` 就是一轮的漂移）。  
  降频后同一个测量值会**连续 4 轮**参与判定，而"2 轮连续"的计数器一碰就满 →  
  会在锚点变旧的**正常**训练里被误触发（回退存档 + lr 减半）。改成用每轮率。

**配套工具（新增两个，都可复跑）**

| 文件                                | 作用                                                                                                                                                                     |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/test_coef_controller.py` | 控制器行为回归 **17 项断言 + η 扫描**。不 import torch（把类源码抠出来 exec），秒级跑完。含"降频不变性""锚点年龄归零""`kl=None` 不得改动 kc"等**只有踩过才会想到**的用例。                                                       |
| `scripts/kl_scale_probe.py`       | 从 history/日志量出 KL 的**每轮率**分布，并对一组候选 `--kl-target` 做**反事实重放**（触发次数 / kc 终值 / 是否撞上限）。本段的结论：峰值率 0.0308 ×1.5 = 0.0462 → 建议 **0.05**，与计划原值一致 —— 也就是说 **0.05 本来是对的，错的只是量纲**。 |

> 教训（值得记进记忆）：**凡是"自适应/退火/门控"这类没有梯度可看的部件，  
> 落地后必须有一个能在几秒内跑完的行为单测，而不是等 600 轮之后看结果反推。**  
> 这次三个缺陷如果留到 M2-A 段末才发现，整整 8 小时的算力会被浪费，  
> 而且会把失败**错误归因**给"蒸馏无效"。

### 5.4 A1 的熵目标在数学上不可达（第五类静默问题，C5）

60 轮验证跑（`reports/_m2a_smoke2.out`）**完整跑完 60/60 轮、无 NaN、无异常**，  
β 0.400→0.321、ε 0.030→0.026、`lr` 1.2e-5→4.0e-6 全部单调按预期退火 ——  
但导出 history 一看，**`ec` 全程钉在 0.010、60/60 轮零变化**。

| 量                           | 实测                     | 计划的隐含假设     |
| --------------------------- | ---------------------- | ----------- |
| H₀（控制器用的段首 25 轮均值）          | **1.0253**             | ——          |
| H* = 0.75·H₀                | **0.7690**             | 这就是目标       |
| H_steady（末 20 轮均值，熵已**饱和**） | **0.9389**             | 假设能降到 0.769 |
| 稳态 / 段首                     | **91.6%**              | **75%**     |
| H − H*                      | **+0.1699（全程为正）**      | 应当穿过 0      |
| `ec` 轨迹                     | 0.010 → 0.010（60 轮零变化） | 应当双向动作      |


**机制**：`ec ← clip(ec·exp(η(H\*−H)), 0.01, 0.5)`。`H > H*` 恒成立 →  
指数项 `< 1` 恒成立 → `ec` 只会**减小**，而它的起点就是下限 0.01 → **无路可走，静默静止**。

这与 A1 要修的旧缺陷（旧阈值规则把 `ec` 钉在 0.03、S1–S3 共 2450 轮**从未动过一次**）  
**是同一类失效** —— 换了公式，失效形态一模一样。

**为什么判读抓不到**：A1c 的三态判据（同一晚刚加）把这种形态归为 **SKIP**  
（"熵全程高于 H* → 控制器按设计保持不动，本窗口不足以判定"）。判据本身没错，  
但后果是 **M2-A 跑完 600 轮，段末判读会报"全部通过"，而 A1 从未生效** ——  
6.6 小时算力白烧，且失败会被**错误归因**给"蒸馏无效"（G1 的判读直接失真）。  
→ 所以 A1c 的 SKIP 文案现在直接点出「若整段一直如此，检查 `--ent-target-ratio` 是否低到不可达」。

**三层防护（已落地）**

| 防护         | 位置                                | 作用                                                                                                                   |
| ---------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **可达性预判**  | `CoefController.step()` 基线窗口结束处   | **第 25 轮**就报出 H* 与稳态的距离，并反推「要立刻接管，ratio 需 ≳ 多少」——不必等几十轮后从"ec 不动"反推                                                   |
| **贴死端点告警** | 同上                                | 明确区分两种端点状态：① `ec` 在下限且 H > H* → 目标偏保守（**不是故障**，预判已报）；② `ec` 在上限且 H < H* → **真故障**（熵奖励开到最大仍推不动 = H* 不可达），连续 25 轮后告警一次 |
| **单测 T9**  | `scripts/test_coef_controller.py` | 6 项断言：两条路径都要触发、告警不刷屏、并把"目标不可达时 ec 静默贴下限"这一 **C5 现象本身**固化成回归用例                                                        |

**顺带修：判读的 H₀ 口径与训练不一致**。判读 A1a/A1c 用 `mean(H[:k])`，  
`k = min(25, n//4)`（60 轮时 **k=15**）；训练用 `--ent-baseline-iters`（**25 轮**）。  
热启动段前 25 轮熵还在下滑，两个窗口均值差 0.03+ → **判读报 `H*=0.790` 而训练日志写  
`H*=0.769`**，报告与实测对不上，而 A1c 恰恰要用训练那个 H*。  
→ 新增 `train_h0()`：从 stdout 的 `[coef] 熵基线 H0=…（段首 N 轮）` 行读**权威值**，  
A1c 优先用它并标注来源；A1a 的"带"仍用本判读窗口标定（那是它的本职）。

**目标重标定**：由新增的 `scripts/ent_gain_probe.py` 定标 —— 用两组**只差  
`--ent-coef`**（0.02 / 0.30）的 12 轮短跑量出 `dH/d(ec)`（其余变量全部锁死：  
`--no-adaptive`、`lr`/`beta`/`eps` 恒定、同 seed、同 ckpt）。  
**没有这个增益就只能在盲猜一个好数字**，而 C5 的教训正是"不要猜"。

### 5.5 M2-A 起动"零输出即死"（第六类静默问题，C6：死的不是输出，是进程树）

**现象**：`m1_launch_segment.py --segment s4a` 打印「✅ 已起（pid XXX，完全脱离会话）」，
但 `reports/_m1_s4a.out` 只有 launcher 写的 2 行，主进程消失、**连启动横幅都没有**；
连续 3 次稳定复现，keep_awake / res_monitor 同样不见踪影。

**排查**（每次只改一个变量）：creationflags 七档"全存活"但父进程都在跑（结论无效）→
torch + mp.Pool 在 DETACHED 下可用（`_spawn_diag.py`，排除）→ 前台跑 iter 1 正常（排除）→
"父进程句柄被 `with` 块 close"像是根因，但决定性实验推翻了它：
**父进程继续存活、t=35 s 只 close 句柄 → t=35→120 文件 1604→1968 B、`poll=None`**
⇒ 句柄关闭毫无影响（Windows 上子进程持独立内核句柄），第 4 假设是**误判**。

**定案**：**沙箱型执行环境在每次调用结束（前台命令返回）时无条件清理整棵进程树**，
与起动姿势无关 —— 实测六档全部阵亡：

| 起动方式 | 命令返回后 |
|---|---|
| `DETACHED+BREAKAWAY_FROM_JOB+NEWGRP` | 一个字节都没写出 |
| `DETACHED+NEWGRP` / 无 flags | 同上 |
| `nohup … & disown` | 只活到第 1 行 |
| `setsid nohup … &` | 文件从未创建 |
| `Popen`（父进程存活 120 s） | ✅ 正常，产出 iter 1 |

`CREATE_BREAKAWAY_FROM_JOB` 的 `Popen` **不报错**但照样被清 ⇒ 清理不是 Job Object，
而是按进程树枚举；`schtasks`（服务托管、天然脱离）被程序黑名单拦截。

**修复（已落地）**：
1. `m1_launch_segment.py` **默认 `--foreground`**（新增 `--detach` 只留给真实终端）——
   原来那个「✅ 已起」的**假成功**是最坑的一环；
2. `selfplay.py --log-file` 接线到 `build_cmd()`：训练进程**自开日志**（append），
   launcher 只写头部后立即释放句柄，两侧互不持引用；
3. `launch()` 加**存活确认 settle**（默认 8 s）：`poll()` 非 None 当场报错 + 打印日志尾
   12 行 —— 不再让人等 6 小时才发现日志没长；
4. `verify_segment_recipe.py` 加结构断言「每段必须有 `--log-file`」（52 → **57 项**）；
5. `m1_autopilot.py::start_training` 同样不持句柄。

**起动协议（M2 全程硬规则）**：

```bash
# ✅ 把 launcher / 自动链挂进平台后台任务（本环境 --foreground 已是默认）
<平台后台任务> → python scripts/m1_launch_segment.py --segment s4a
# ❌ 前台命令跑 → 命令一返回，整棵树（含训练）被清
```

M2 的收尾与门禁同样受此约束 → 新增 **`scripts/m2_chain.py`**（M2 专用自动链：
A 收尾 → G1 分支 → M2-B → G2×3 + G3 → 总报告，全阶段幂等）与
**`scripts/gate_watch.py`**（等周期存档 → 1200 副判读 → 打判决，见 §8 第 6 步）。

### 5.6 M2-B 的 G2 门禁被"阻塞式起动"挤到段末（第七类静默问题，C7）

**现象**（2026-10-15 14:05 体检时发现）：训练已到 **506 轮**，而 `reports/G2_s4b_it0400.json`
不存在、链日志在起动后一行未再输出。

**根因**：`m2_chain.py` 用 `ensure_training(...)` → `launch(..., foreground=True)` 起训练，
而 `launch()` 的 `foreground` 参数**同时承担了两件事**：

| 语义 | 旧实现 |
|---|---|
| 怎么起（跟随调用方 vs 脱离会话） | `foreground=True` → 裸 `Popen`（无 DETACHED 标志）|
| 起完要不要等 | `foreground=True` → `proc.wait()` **阻塞到训练结束** |

于是 `ensure_training()` 一直阻塞到 1200 轮跑完，**只有那时才会执行 G2@400 / G2@800**。
判据的数值本身不受影响（同一批存档、同一牌池、同一 seed），但**门禁的意义被抹掉了** ——
G2@400/800 存在的唯一理由是「**撤教师塌陷的早警**」（§7 风险表：G2 第 400 轮 vs master
不升反降 → 拉长退火 / 保留残差）。排到 1200 轮之后，塌陷只能"事后知道"，无法止损。

**修复**：把两个语义**解耦** ——
1. `m1_launch_segment.launch()` 新增 `wait: bool = True`（默认不变，对其他调用方零影响）；
   `foreground=True, wait=False` = 跟随调用方起、但**起完立即返回**；
2. `m2_chain.ensure_training(..., block: bool = True)` 透传；**M2-B 用 `block=False`** →
   链起完训练立刻进入门禁循环，`gate_watch` 一边等 `it0400` 存档落盘、一边让训练继续跑，
   到点即判（这才恢复早警）；
3. 重跑 A 段分支仍用阻塞式（那段确实要等结果才能决定 B 的起点）。

**教训（通用）**：一个布尔参数**同时控制两件正交的事**时，迟早会用错一次 —— 尤其在
"起动 + 等待"这种每个调用方的意图都不同的场景。要么拆成两个参数，要么把语义写进函数名。
（同族问题：C6 的 `--foreground` 也一度既是"起动姿势"又是"是否阻塞"。）

### 5.7 M2-B 配方让模型变弱（第八类静默问题，C8 —— 前七类都是"工具/代码"错，这一个是"配方"错）

**现象**：`s4b`（1200 轮，β=0）跑到第 500 轮时体检，同池配对判读显示
**比 A 段末低 2.18 ± 0.65（3.3σ）**，且 500 副早读显示 400→500 轮还在继续跌

|---|---|
| `dushan_m2_a_it0600`（A 段末） | **−1.046 ± 0.448** |
| `dushan_m2_b_it0500`（B 当前） | **−3.228 ± 0.473** |

**病因：不是"撤教师"**。A 段 β 在 300 轮内线性退到 0，**it300→it600 这 300 轮全是 β=0**
且 vs master 从 −1.413 涨到 −1.046 ⇒ "没有教师就学不动"与事实矛盾。真正变的是**训练场与熵目标**：

| `--snapshot-pool` ★ | `dushan_master` | `dushan_m1_s3`（**更弱**） |
| `--master-seat-prob` | 0.30 | 0.20 |
| 熵目标 `H*` | 0.975（H₀=1.026 实测） | 0.836（H₀=0.880 实测） |

两处**容易误解的机制**：
1. `--snapshot-pool` **不是"自身快照池"，而是一批固定的常驻对手模型**（`selfplay.py:1170`）
   ⇒ 改它等于换目标函数，属于**配方变更**，不该当成"换个池子"的小事；
2. `H* = ratio × 本段实测 H₀` —— **续训段的 H₀ 天然比上一段低**（起点模型更尖），
   于是同一个 ratio 给出的绝对目标随之下降（0.975 → 0.836）⇒ 政策被推得更尖、探索更少。
   修法不需要改代码：`--ent-baseline 1.026` 直接把 H₀ 钉成绝对值。

**处置**：第 533 轮主动停机（存档与日志全部保留，可 `--resume` 作对照组），
新增段 **`s4b2`** = A 段配方原样 + β=0 单变量（池回 master、座位比回 0.30、
`--ent-baseline 1.026` 钉 H\*=0.975、lr-min 回 4e-6、ε 只轻退火 0.015→0.01），600 轮。
完整取证与推导见 **`reports/M2B_塌陷诊断与配方修正.md`**。

**门禁**：G2@300（早警，对 A 段末比单调不减）+ G3@600（追平/超越双档）。
**止损线**：若 G2@300 仍 ≤ −1.05 → 停跑重查（说明"场强度"不是唯一病因），不再烧后 300 轮。

**通用教训**：
- **"相对目标"在续训段会静默漂移** —— 跨段续训必须用绝对目标或显式传上一段基线；
- **早警门禁必须跑在训练进行中**（C7 的后果：这次靠人工体检才发现塌陷）；
- **内部评测只能看趋势，不能当判据**（段间漂移 ≈1.5 分，跨段比较一律用同池配对判读）。

## 7. 风险与回退

| 风险                               | 信号                              | 缓解 / 回退                                                   |
| -------------------------------- | ------------------------------- | --------------------------------------------------------- |
| **撤教师塌陷**（Reincarnating RL 明确警告） | G2 第 400 轮 vs master 不升反降       | 慢退火（300 轮）；保留 0.02 残差；塌陷则把退火拉长到 600 轮                     |
| **蒸馏把上限钉在 master**               | A 段末 vs master 卡在 ≈0 且 B 段不动    | β 必须退火到 0（硬要求）+ reverse-KL 保模式覆盖；必要时 B 段中段重启 β=0.05 短脉冲   |
| **Goodhart：只对 master 变强**        | vs master 涨、vs 教师/roundrobin 不涨 | 终验收强制并列报告独立口径（G3）                                         |
| **熵目标设太高 → 强度反降**                | G2 首个 400 轮不升 且 H > 1.35        | 下调 H* 到 0.65·H₀；ε 收到 1%                                   |
| **辅助头污染主策略**（R3 类事故）             | discard 头输出分布整体偏移               | 输出层零初始化 + 20 轮 ramp + 单独监控 discard logits 与熵；异常则权重砍到 0.02 |
| **吞吐修复不如预期**                     | 修复后 >55 s/轮                     | 退到"只减 eval + 减重建频率"；进一步可做采集/更新流水线化                        |
| **系统冻结**                         | res_monitor 空洞 >180 s           | keep_awake + res_monitor 双守护（沿用 M1 的做法）                   |
