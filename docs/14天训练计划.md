# 14 天精确训练计划（2026-11-06 → 2026-11-19）

目标：训出 **M1（≈9.8M）+ encoder v3** 新基座，贪心 ≥ 现 master+N32，
同搜索配置下 +3~6 分/副；产出可复用 ExIt 管线与显著性报告。

硬件：Mac M5 / 32GB / 10 核 GPU（MPS），全程 **fp32**（bf16 慢 47×，禁 autocast）。
机器独占 24/7；worker 默认 6 个（留 4 核给系统/交互，约 −15% 速度）。

### D2–D9（11-07 → 11-14）ExIt 主循环 ｜ 对应任务 #19

每天 2 轮（R1–R16），单轮 6h 时间盒：

| 时刻 | 内容 | 细节 |
|---|---|---|
| +0:00 | rollout 出状态 | R1 用 master rollout；R2 起**当前最佳学生 rollout（DAgger 聚合）**；温度 0.4；记录合法动作≥2 的全部决策点（四家座位） |

| +2:30 | 训练 | 窗口 400k（滑动混合历史轮 = DAgger 数据聚合）；从上一轮最佳 ckpt 继续；早停 |
| +4:30 | 闸门 A+C | A：300 seed 新贪心 vs master 贪心；C：50 seed 新贪心 vs N32；通过 → 该 ckpt 升为「最佳」；不通过 → 保留旧最佳，数据仍进窗口 |
| +5:30 | 记录/备份 | 轮日志写 `reports/exit_log.md`；ckpt 双份（`models/exit_best.pt` + `models/exit_rNN.pt`） |

- **R3/R6/R9/R12/R15 末追加闸门 B**（四座约 +3h，当日改 1 轮为佳）。
- **R4 起**：开 aux 头（`aux=T`，标签：自家向听桶/三对手听牌/牌墙余量/27 牌危险度，
  采集器现算，aux 损失权重 0.2）——先只在新 ckpt 上启用，旧窗口数据 aux 标签缺失时该损失按 0。
- **R8 起**：lr 5e-4 精修。
- **D8 前**：PPO 奖励 wrapper 设计定稿 + 单测（多局分差终端 + 势函数塑形，§0 口径）——
  与 ExIt 并行做，避免 D10 开 RL 时才发现弱信用分配拖累蒸馏数据利用率（外部建议 #3）。
- **增速决策点（R3 末、R6 末）**：若闸门 A 连续两轮 p>0.2 或均值≤0 → 触发以下**之一**并记录：
  1. τ 从 1.0 → 0.5（更接近 argmax 模仿）；
  2. 损失加 Q-MSE 项（对合法动作回归教师 Q，权重 0.3）；
  3. 教师升级为 `n_det=64, ply=3`（成本 ×2，标注时间 →4h/轮，当日改 1 轮）。
  三选一，先 1 后 2 再 3，禁止同时改两项。
- **并行路（D5 起，若机器余量>30%）= Oracle Guiding 试点（外部建议 #2）**，两层递进：
  - **P2a 标签侧退火（先做，零编码改动）**：教师 Q 改为
    `q* = α·Q_oracle + (1−α)·Q_pimc`，α 从 1.0 线性退火到 0.0（跨 2 轮）。
    `Q_oracle` = 跳过 determinize 的完美信息搜索（需给 `annotate.rs` 加 `--oracle` 开关，工作量小）。
    原理：学生以公开信息逼近完美信息教师的决策 = 隐藏信息推理的直接监督。
    标注 20k 状态训对照 ckpt，闸门 A 对比主路，**显著更优则并入主路重跑后续轮**。
  - **P2b 输入侧退火（仅当 P1+P2a 仍不够，成本高慎入）**：全信息编码预热 →
    掩码退火（对手手牌通道训练期可见、按比例退火到全掩码）。需临时扩编码器
    （破 v3 红线，仅训练期），部署前必须蒸回合规输入口径。

### D10–D12（11-15 → 11-17）PPO-lite RL 精调 72h ｜ 对应任务 #20
- 起点：ExIt 最佳 ckpt；教师混入 teacher_prob=0.08（教师 = N32 搜索）。
- **奖励口径（外部建议 #3，D8 前已定稿实现）**：
  - episode = 4 局一圈（轮庄），**终端奖励 = 4 局净分差之和**（多局分差，
    降单局随机性、与评测「分/场」口径对齐）；
  - **势函数塑形**：`r' = r + γΦ(s') − Φ(s)`，`Φ(s) = 8·V_θ(s)`（policy-invariant，
    与 VALUE_SCALE=8 同量纲）；
  - **RVR 升级位**（势函数塑形后训练方差仍高时）：期望奖励网络
    `E[R|s]` 做基线减除（Reward Variance Reduction，CoG'22）。
- 超参沿用 master 配方：96 局/iter、epochs 2、batch 512、lr 8e-6、temperature 0.95、
  reward_scale 8、value_coef 0.5、ent_coef 0.01、kl_coef 0.02、kl_target 0.25、ent_floor 0.45。
- 每 8h 一次闸门 A+B+C；**连续两次退化 → 立即回退 ExIt 最佳**，把剩余额度改为再跑 3 轮 ExIt。
- RL 期间不改网络结构/编码器。

### D13–D14（11-18 → 11-19）终评交付 ｜ 对应任务 #21
1. **500 seed 三项配对**（四座旋转，analyze.py 出显著性）：
   - 新贪心 vs master 贪心（网络等效）；
   - 新+N32 vs master+N32（线上等效）；
   - 新贪心 vs 现 N32（「搜索蒸进网络」的直接度量，目标 ≥ −2 分/副）。
2. ONNX 导出 + CoreML 服务器接入（档位零改动），在线 `?touch=1` 页面冒烟 10 步。
3. 报告 `reports/14天训练报告.md`：曲线、每轮闸门表、显著性、失败分支记录。
4. 全部 ckpt/数据保留；`runs/exit_*` 归档不删。
5. **推理时搜索决策门（外部建议 #4）**：只有当 P1 蒸馏 + P2 Oracle Guiding 走完、
   新贪心仍明显弱于 N32（终评差 > 2 分/副且显著），才立项外挂重要性采样 MCTS；
   否则维持「搜索价值蒸进网络、推理不挂搜索」的结论并写进报告。

## 3. 风险与预案

| 风险 | 预案 |
|---|---|
| 训练器/标注器 bug，冒烟不过 | D1 当天修；顺延吃余量，不带病进 D2 |
| ExIt 无增益（R3 决策点） | τ/Q-MSE/强教师三选一；仍无益 → 剩余时间全转 oracle 教师 + 数据增广（花色置换） |
| M1 迭代太慢（>3h/轮训练） | batch 256→512，或减窗口至 200k；不换回 mid（用户已定 M1） |
| 配对评测假阳性 | 正对照每 4 轮；不显著不晋升 |
| **自对弈幻觉**（自对弈指标与外部强度脱钩，11-04 批次已证实） | **所有决策只认冻结基线池配对**（闸门 A/B/C + 正对照）；自对弈胜率只准记录、不准作为任何晋升/回退依据 |
| RL 奖励方差大、信用分配弱 | 多局分差终端 + 势函数塑形先行（§0）；不足则 RVR 期望奖励基线；再不足缩短 RL、回 ExIt |
| 教师天花板 | 学生上限 ≤ N32；oracle 教师是突破手段，D5 起试点 |
| 机器过热降频 | 垫高+外接电源；worker 6；温度异常时 worker → 4 |
| RL 精调退化 | 连续两次退化即回退，改跑 ExIt |

## 4. 交付判定（成功标准）

- **主目标**：新+N32 vs master+N32 显著为正（p<0.05）≥ +2 分/副；
- **达成**：≥ +3 分/副；
- **超额**：新贪心 ≥ 现 N32（搜索等效搬迁）；
- **保底**：无论显著与否，交付完整曲线/报告/管线（11-04 报告同口径）。

### 6.8.3 前瞻排查：seed 编号区间重叠是伪风险（已排除，不改代码）

**现象**：`night_run.py:183` `seed0 = 600_000 + r*10_000`；`annotate.rs:294`
`Rng::new(seed0 + tid*10007)` 给 4 个 worker 各自派生 RNG 种子。因 `tid*10007` 偏移，
从 **R8** 起部分 worker 的种子编号会落入 710000/720000 区间；R11（seed0=710000）的 w0、
R12（720000）的 w0 更直接等于闸门 A/C 的 `--seed0`。表面看违反 §0「评估 seed 池与 rollout 隔离」。

**核实结论：伪风险，隔离在实现层成立**：

| | 标注（训练 rollout） | 评估（闸门 A/C、终评） |
|---|---|---|
| PRNG | Rust `xorshift64*` `Rng::new(seed\|1)`（`rng.rs` 注「无需与 Python 对齐」） | Python `random.Random(seed)`（`rules.py:146`） |
| 洗牌 | `Rng::shuffle` Fisher-Yates（`below(i+1)` 取模） | `random.Random.shuffle` |
| 流语义 | 每 worker 单条长 RNG 流连续发 ~2000 局，种子仅定起点 | 每 seed 重置一个新 `random.Random` 发 1 局 |
| 牌墙 | `full_deck()` + `rng.shuffle` + `rng.below(4)` 定庄 | `full_deck()` + `self.rng.shuffle` + 独立 dealer |

PRNG 不同族、洗牌算法不同、发牌流结构不同 ⇒ **即使编号相同也不会生成相同牌墙**，
不存在「评估牌墙进入训练 rollout」的数据泄漏。

**处置**：不修改 `night_run.py`（长驻驱动不重载源码，改了对当前进程无效，§6.6.1；
且会引入无谓变更与「改了没生效」的错觉）。本节登记为已排除项，供后续自检避免误判。
若未来某次**自然重启**后希望彻底消除编号层面的审计歧义，可在重启窗口把 rollout seed0 迁至
`2_000_000 + r*10_000`（与 710000/720000/终评池均不相交），属低优先级、非必需。

def ppo_init(r):
    if not (ROOT / "runs/ppo_rechain").exists():
        prev = ROOT / f"models/exit_p{r-1:02d}.pt"
        if prev.exists():
            return prev            # 续链：经验跨轮累积
    return latest_pt()             # 无上一条链 / 急停标志 → 回 DAgger 现最佳

### §6.27.6 **PPO 晋升在结构上不可达 —— 这是设计，不是故障**

链路：PPO 晋升要求「闸门 D(vs 现最佳) p<0.05 且均值>0」**同时**闸门 A 通过；而闸门 D 的
基线是**同轮刚晋升的 DAgger 最优**，其 300 seed SE≈0.5 分 ⇒ 需要 **+1.0 分以上**的真实增量
才能显著，而单轮 PPO 位移 ≈0.005 KL 量级，几乎不可能达到。推论：

1. `exit_best.pt` 在可预见的轮次里**会一直等于 DAgger 的 rNN**，PPO 只做平行支线；
2. 因此 **`models/web_best.pt` 永不跟随 PPO**（§6.25 纪律 B 得到强化，不只是"不要"，而是"不会"）；
3. PPO 的全部价值只能通过**终评两段式 best-of** 兑现（ckpt 全留档、独立池复赛）；
4. 所以后续任何「PPO 一直没晋升」的观察，**一律不得解读为 PPO 无效**，只看 `P{r}−R{r}`。

### §6.28.5 【关键定量发现】配对差分不降方差（ρ≈0）

`SE(R09−R08)=0.570 ≈ √(0.399²+0.415²)=0.576` ⇒ 逐 seed 配对的**方差几乎无收益**。原因：

3. 因此 **§8.1 原判「P0 交付缺陷」应降级为 P2 方法论完备性**：`exit_best` 逐轮覆盖在平台期
