## 关键事实（已核实）

- **c4_it2280 结构**：m0 preset = channels 128 / blocks 12 / hidden 512 /
  global_dim 130 / in_channels 63；**无**空间头、**无** aux 头。
- **推理契约**（JS 侧照此实现）：
  `encode_v3(game, actor) → (tiles f32[63×27] → reshape(1,63,3,9), glob f32[1,130])`
  → ONNX 四头输出 `discard[?,28] / self_kong[?,28] / respond[?,4] / value[?,1]`
  → `logits[head][:mask.len]`，mask 外置 −1e9 → temperature=0 取 argmax
  → `index_to_action(head, idx)`（respond 头 = [pass,peng,minggang,hu]；
  discard 头 idx27=HU；self_kong 头 idx27=PASS）。
- **A1 对拍**：`scripts/export_onnx.py`；torch vs ORT **真实局面 maxdiff 4.58e-05**
  （判据 1e-3，PASS）。rand 垃圾输入最大 1.95e-03（20 层卷积放大，无意义，不判）。
- ONNX 产物：`models/standalone/dushan_m2_c4_it2280.onnx`（15.5 MiB，opset 17，
  dynamic batch）。models/standalone/ 被 models/* 规则 gitignore（可再生成，不入库）。
- **单文件内嵌路径**：`ort.env.wasm.wasmBinary` 可直接喂 ArrayBuffer ⇒
  wasm 可 base64 内嵌；权重同理。严格单 HTML ≈ 16.3MB(onnx) + 15MB(wasm) +
  0.45MB(js) + UI，base64 膨胀 ×4/3 ⇒ 约 45MB。可选瘦身：fp16 权重（−7MB），
  待 A5 强度核账后决定是否采用。

## 差分对拍体系（移植质量的生命线）

- **语料**：`scripts/export_standalone_corpus.py` → `reports/standalone_corpus.json`
  （6 局随机对局；每步 legal_actions + **全量 __dict__ 状态 dump** + 动作；
  每 4 步采样 encode_v3 观测 + ONNX logits 基准；终局 result）。
  状态序列化形状：set→`{__set__:[...]}`、dict→`{__dict__:[[k,v]...]}`、
  Enum→str(value)；排除 rng/cfg。
- **验收台**：`node web/standalone/replay_harness.js`
  - JS 引擎按语料重放（墙预设注入，**不移植 MT19937**）；
  - 每步对拍：合法动作表（**顺序敏感**）+ 状态全量 dump（数字容差 1e-9）；
  - 采样步对拍：编码器 tiles/glob（1e-6）+ mask + head；挂载 `Engine.ortInfer`
    后再加 logits（1e-3）；
  - 终局对拍 result。
- **为什么不用同 seed 对局**：Python 用 MT19937 洗墙，JS 复刻 RNG 成本高且无收益；
  墙注入重放同样能逐位验证引擎语义。

## 已知坑（教训）

1. `DushanGame` 用 `DushanConfig`（非 RulesConfig）——kaiju_fanji 等独山字段。
2. 推进用 `game.step(action)`（不是 apply）；终局判定 `game.phase == Phase.OVER`。
3. obs.tiles 形状 (63,27)，glob (130,)——喂网络前各自 reshape 成 (1,63,3,9)/(1,130)。
4. harness 的 result 断言：Python 侧 dict 被 wrap 成 `{"__dict__": [...]}`，比较前要解包。
5. obs_every 采样 + 每步全量 dump 的语料 ≈ 2.1MB/6 局——继续加局数要考虑体积。
